# Design Doc: Поиск похожих каналов — v1

## 1. Проблема / Контекст

Каждому агенту платформы нужен поток профильных каналов — для мониторинга и DM-воронки.
Существующая фича поиска каналов (`channel-discovery`) опирается на внешний платный
агрегатор (TGStat): поиск идёт по ключевым словам и стоит денег за объём.

При этом у Telegram есть собственный бесплатный сигнал «похожие каналы» — тот самый блок
рекомендаций внизу любого канала в клиенте. Это дешёвый источник тематически близких
каналов: у агента уже есть набор проверенных каналов, и от каждого из них можно получить
список похожих. Сейчас этот сигнал не используется — профильные каналы добываются только
платным поиском по словам.

Нужен дешёвый дополнительный канал пополнения: брать уже имеющиеся каналы агента как
отправные точки и находить от них похожие, расширяя тематический кластер без затрат на
внешний платный поиск.

## 2. Цели

**Пополнять каналы агентов профильными каналами из бесплатного нативного сигнала
Telegram «похожие каналы»** — как дешёвое дополнение к платному поиску по ключевым словам,
а не замена ему.

Задачи, ведущие к цели:

- Использовать уже имеющиеся каналы каждого агента как отправные точки поиска.
- **Начинать обход с самых «живых» отправных точек:** при раннем стопе по целевому
  числу первыми раскрутить рекомендации каналов с наиболее активной аудиторией — их
  граф похожих релевантнее.
- Находить тематически близкие каналы и расширять кластер от находки к находке.
- Отбирать каналы по минимальному порогу подписчиков, заданному оператором.
- Закреплять каждый новый канал за одним агентом без пересечений с другими агентами.
- Ставить отобранные каналы в очередь вступления агента; само вступление происходит
  позже своим чередом.
- Беречь аккаунты агентов: останавливать поиск у агента, если Telegram начинает
  ограничивать его активность.

## 3. Как работает

Оператор запускает поиск и задаёт минимальный порог подписчиков и целевое число новых
каналов на агента. По желанию он может ограничить набор агентов и окно наблюдения для
приоритизации; по умолчанию обрабатываются все агенты, окно — недавний период.

Система проходит по агентам по очереди. Для каждого агента:

1. Берёт **все каналы этого агента** как отправные точки (seed-каналы, уровень 0). Для
   каналов-вещаний это сам канал, для мегагрупп-обсуждений — привязанный к обсуждению
   broadcast-канал.
2. **Упорядочивает seed-каналы по вовлечённости аудитории** за недавнее окно и обходит
   их от самого живого канала к наименее активному.
3. От каждой отправной точки находит похожие на неё каналы, затем находит похожие на
   уже найденные — так тематический кластер расширяется от находки к находке.
4. Каждый найденный канал проверяется по порогу подписчиков: каналы ниже порога
   отсеиваются.
5. Каждый новый канал, прошедший порог, закрепляется за этим агентом навсегда и ставится
   в его очередь вступления.

**Приоритизация seed-каналов по вовлечённости.** Раскрутка графа похожих может оборваться
рано — на целевом числе каналов. Чтобы при раннем стопе успеть обойти рекомендации самых
ценных каналов, seed-каналы перед обходом упорядочиваются по вовлечённости их аудитории
за недавнее окно, и обход идёт от самого живого канала к наименее активному. Вовлечённость
оценивается тем, насколько активно аудитория читает посты канала относительно его размера,
— так крупные и небольшие каналы сравниваются на равных. Каналы, у которых вовлечённость
определить нельзя (нет постов в окне, неизвестно число подписчиков или просмотры), считаются
наименее живыми и обходятся в последнюю очередь. Упорядочиваются только seed-каналы
(уровень 0); каналы, найденные на следующих уровнях, не пересортировываются.

**Расширение кластера строго по уровням.** Обход идёт в ширину: на следующий уровень
система переходит только после того, как пройден весь текущий. Похожие раскручиваются
только у кандидата, прошедшего порог подписчиков, — не прошедший канал своих похожих в
обход не отдаёт, и ветка графа от него не растёт. Достижение целевого числа завершает
обход агента целиком, не переходя на следующий уровень.

**Непересечение каналов между агентами.** Один канал может принадлежать только одному
агенту. Если найденный канал уже закреплён за другим агентом, он пропускается — повторно
не назначается. Так каналы агентов не пересекаются ни внутри прогона, ни между прогонами.

**Развязка поиска и вступления.** Сам поиск только наполняет очередь вступления. В каналы
агент вступает позже, своим чередом — это отдельный механизм агента, работающий по
расписанию. Оператор, запустивший поиск, получает наполненную очередь, а не сразу
вступления.

По завершении оператор получает отчёт: сколько новых каналов найдено и поставлено в
очередь по каждому агенту, и чем закончился поиск у каждого агента — набрал целевое
число, дошёл до естественного конца или был прерван ограничениями аккаунта.

## 4. Архитектура

**Компоненты.** Логика обхода — в `src/features/discovery/similar.ts` (политика обхода, без
LLM); MTProto-вызовы инкапсулированы в `TelegramService` (`src/core/telegram/service.ts`).
Реестр найденных каналов и закрепление за агентом — `src/core/db/discovery.ts`
(`normalizeChannelLink`, `isKnownChannel`, `registerChannel`); постановка в очередь
вступления — `src/core/db/join-queue.ts` (`addJoinQueue`). Точка запуска — скрипт
`src/scripts/discovery-similar.ts`, обёрнутый скиллом `skills/discovery-similar/`.

**Последовательный обход.** Агенты обрабатываются строго по одному, каждый на своей
сессии (`loadAccount` → обход → `disconnect`). Параллельного обхода нет: за счёт
последовательности в реестр пишет ровно один обход, конкуренции за закрепление каналов
нет. Падение сессии одного агента не роняет прогон — ошибка фиксируется, прогон идёт
дальше.

**Обход внутри агента.** Seed-каналы восстанавливаются из диалогов (broadcast — напрямую,
мегагруппа — через привязанный broadcast-канал), затем оцениваются по вовлечённости
(median просмотров за окно / число подписчиков — ~1–2 MTProto-вызова на seed) и
сортируются. Сам обход графа — поиск в ширину на единой FIFO-очереди: отсортированные
seeds в начале, найденные кандидаты добавляются в конец. Кандидат проходит дедуп по
реестру и гейт по подписчикам; прошедший закрепляется за агентом (finder-first-wins) и
ставится в очередь вступления, после чего его похожие добавляются в очередь на следующий
уровень.

**Темп обхода и время прогона.** Обход выполняет MTProto-вызовы строго последовательно с
паузой 3–7 с (`pacingMs`) после каждого вызова на всех этапах (восстановление seed,
оценка вовлечённости, запрос рекомендаций, проверка подписчиков), чтобы не провоцировать
анти-флуд Telegram и не подвергать риску сессию агента. Одиночный FLOOD_WAIT
отрабатывается ожиданием и повтором; два FLOOD_WAIT подряд останавливают обход этого
агента, и система переходит к следующему (безопасность аккаунта важнее добора каналов).
Следствие: при сотнях seed-каналов прогон одного агента занимает десятки минут — это
штатное поведение, а не зависание; в частности, долгая тишина в логах после строки
«восстанавливаю seed-каналы…» нормальна, потому что внутри цикла восстановления
промежуточных логов нет.

**Полнота рекомендаций зависит от Premium.** Без Premium у аккаунта агента Telegram
отдаёт список похожих каналов усечённым — кластер находок будет беднее. В v1 это
ограничение принимается и специально не обходится (см. Future Work).

## 5. Альтернативы

### Метрика приоритизации seed-канала

Выбрана оценка вовлечённости аудитории относительно размера канала. Рассмотренные и
отклонённые варианты:

| Альтернатива | Почему отклонена |
|---|---|
| Просмотры поста без поправки на размер канала | Не уравнивает каналы разного размера: крупный канал всегда «активнее» небольшого, хотя его аудитория может быть пассивнее. Выбранная оценка соотносит активность с числом подписчиков. |
| Частота постинга | Меряет активность *автора*, а не вовлечённость *аудитории*; много постов с нулём просмотров — не сигнал ценности. |
| Реакции и комментарии на пост | Дороже в сборе, у части каналов реакции/комментарии отключены; чтение постов — самый универсально доступный сигнал активности аудитории. |
| Усреднённая активность, чувствительная к выбросам | Закреплённый или один виральный пост искажает оценку. Выбран устойчивый к выбросам способ агрегации (медиана). |

### Раскрытие уровней обхода

Выбрано: **на следующий уровень раскрываются только кандидаты, прошедшие порог
подписчиков** (не прошедший канал в обход своих похожих не отдаёт).

| Альтернатива | Почему отклонена |
|---|---|
| Раскрывать всех кандидатов уровня, а порог применять только при постановке в очередь | Раскручивал бы граф от каналов ниже порога подписчиков — лишняя работа и риск ухода в нерелевантные/мелкие кластеры. Порог как условие раскрытия держит обход в зоне качественных каналов. |

## 6. Метрики успеха

- **Пополнение очередей:** сколько новых каналов поставлено в очередь вступления за прогон,
  в разбивке по агентам.
- **Доля прерванных поисков:** у скольких агентов поиск завершился прерыванием из-за
  ограничений аккаунта, а не естественным концом, — сигнал о здоровье аккаунтов и о том,
  насколько агрессивен поиск.
- **Инвариант непересечения:** число каналов, закреплённых более чем за одним агентом = 0.
- **Вклад относительно платного поиска:** доля новых каналов, добытых этим источником,
  на фоне платного поиска по ключевым словам.
- **Эффект приоритизации:** доля целевого числа, набранная из рекомендаций самых живых
  seed-каналов (верхней части упорядоченного списка), — насколько ранний стоп
  действительно раскручивает самые активные каналы.

## 7. Future Work

- **Параллельный обход агентов** — в v1 агенты обрабатываются по очереди.
- **Учёт вовлечённости** как критерия качества при отборе, в дополнение к порогу
  подписчиков.
- **Обход усечения без Premium** — расширение охвата поиска для аккаунтов без Premium.
