# Требования: Авторотация каналов, покинутых из-за бана — v1

> **О чём документ.** Проблема, доменная модель, цель, требования и критерии
> приёмки — уровень бизнес-аналитики (что и почему, для кого). Техническое
> решение (как именно это реализуется) — в парном `architecture.md` (архитектор).
>
> Это базовая версия v1 — текущее (действующее) поведение авторотации. Новая
> логика выбора целевого агента по истории посещений описана отдельно в
> `requirements-v2.md`.

## 1. Проблема и контекст

Когда агент покидает канал из-за бана, канал остаётся закреплённым за этим
аккаунтом и не приносит пользы: писать в него забаненный аккаунт не может.
Авторотация переносит такие каналы на другой активный аккаунт той же платформы,
чтобы канал продолжал обрабатываться, а нагрузка распределялась между агентами.

Аудитория: платформа (суточный кросс-агентный скилл авторотации) и владелец,
отвечающий за распределение каналов между аккаунтами.

## 2. Цель

- Возвращать в работу каналы, покинутые агентом из-за бана, переназначая их
  другому пригодному агенту.
- Переносить только те каналы, для которых есть техническая возможность повторного
  вступления (есть публичная ссылка).
- Распределять переносимые каналы между агентами равномерно по текущей нагрузке.
- Не назначать канал агенту, у которого он только что был забанен.

## 3. Доменная модель

| Термин | Что это |
|---|---|
| Кандидат на ротацию | Канал в статусе «покинут из-за бана» (`leaved_from_banned`) с заполненным публичным именем (`channelUsername`) |
| Публичное имя канала | Юзернейм канала, дающий ссылку для повторного вступления; без него передать канал некому |
| Агент-источник | Агент, у которого канал был забанен и от которого канал переносится |
| Активный агент-цель | Агент, пригодный для получения ротируемых каналов: без активного ограничения и с включённым монитором |
| Активное ограничение | Действующая запись в реестре ограничений агента, временно выводящая его из работы |
| Монитор | Задача агента, читающая каналы; хотя бы одна включённая задача мониторинга означает, что агент работает |
| Активная нагрузка агента | Число каналов агента в статусах, не исключённых фильтром активности |
| Реестр закрепления | Учёт того, за каким агентом закреплён канал (используется при применении назначения) |
| Очередь вступления | Список ссылок, в которые целевой агент должен вступить |
| `skipped_no_username` | Счётчик в сводке прогона: покинутые из-за бана каналы без публичного имени, не ставшие кандидатами |

Модель внутренняя (жизненный цикл канала и распределение внутри платформы), внешними
источниками Telegram не подтверждается и в них не нуждается.

## 4. Ограничения среды

- Повторное вступление в канал возможно только по публичной ссылке; для приватного
  канала без публичного имени ссылки для повторного вступления у платформы нет.
- Авторотация запускается отдельным системным суточным таймером кросс-агентно, вне
  per-agent диспетчера и его очереди задач.
- Между прогоном авторотации и ближайшими прогонами скилла выхода из забаненных
  каналов должно проходить не менее 12 часов, чтобы статусы каналов успели
  устояться до переноса.

## 6. User Stories

**US-1 (R1, R2).** Как платформа, я хочу собирать в кандидаты только покинутые из-за
бана каналы с публичной ссылкой, старые первыми, — чтобы переносить лишь те каналы,
куда целевой агент реально сможет вступить.

**US-2 (R3).** Как платформа, я хочу считать целью только агентов без активного
ограничения и с включённым монитором, — чтобы канал не уходил аккаунту, который не в
работе.

**US-3 (R4).** Как владелец, я хочу распределять кандидатов round-robin по возрастанию
текущей нагрузки агентов с фиксацией порядка на прогон, — чтобы каналы не оседали на
одном аккаунте, а нагрузка выравнивалась.

**US-4 (R5, R6).** Как платформа, я хочу закреплять канал за целевым агентом, ставить
его в очередь вступления и снимать у источника, не назначая канал обратно источнику, —
чтобы перенос был полным и канал не вернулся забаненному аккаунту.

**US-5 (R7).** Как оператор, я хочу, чтобы авторотация шла отдельным суточным
кросс-агентным запуском с отступом ≥12 часов от выхода из забаненных каналов, — чтобы
прогон был предсказуемым и не конфликтовал по времени.

## 7. Требования

- **R1.** Система должна по всем агентам платформы находить каналы в статусе
  «покинут из-за бана» с заполненным публичным именем и упорядочивать их по времени
  обновления статуса по возрастанию (старые — первыми).
- **R2.** Каналы «покинут из-за бана» без публичного имени система не должна включать
  в кандидаты и должна учитывать их отдельным счётчиком `skipped_no_username` в сводке
  прогона.
- **R3.** Агента система должна считать доступной целью только при одновременном
  выполнении двух условий: у него нет активного ограничения И у него включена хотя бы
  одна задача мониторинга. Агент-источник при этом не исключается из пула целей для
  чужих каналов — исключение действует только для его собственного канала (R6).
- **R4.** Список активных агентов-целей система должна один раз в начале прогона
  отсортировать по возрастанию активной нагрузки, зафиксировать этот порядок на весь
  прогон (не пересчитывая после каждого назначения) и распределять кандидатов по нему
  round-robin, начиная с наименее загруженного; при равной нагрузке порядок между
  такими агентами определяется случайно.
- **R5.** Для каждого кандидата с подобранным целевым агентом система должна выполнить
  перенос: закрепить канал за целевым агентом в реестре, поставить ссылку канала в
  очередь вступления целевого агента и удалить строку канала у агента-источника.
- **R6.** Целевым агентом для канала система не должна выбирать агента-источник
  (у которого канал был забанен); при совпадении выбор round-robin сдвигается на
  следующего доступного агента.
- **R7.** Система должна запускать авторотацию отдельным системным таймером раз в
  сутки, кросс-агентно (не через per-agent диспетчер и очередь задач), со временем
  запуска, обеспечивающим отступ не менее 12 часов от ближайших прогонов выхода из
  забаненных каналов.

## 8. Критерии приёмки

- **AC-1 (R1).** Канал со статусом «покинут из-за бана» и непустым публичным именем
  включается в список кандидатов на перенос.
- **AC-2 (R2).** Канал со статусом «покинут из-за бана» и пустым публичным именем не
  включается в кандидаты и учитывается счётчиком `skipped_no_username` в сводке прогона.
- **AC-3 (R3).** Агент с активным ограничением не рассматривается как цель ни для
  одного кандидата в прогоне.
- **AC-4 (R3).** Агент без включённой задачи мониторинга не рассматривается как цель,
  даже если у него нет ограничений.
- **AC-5 (R4).** При ровно одном кандидате он назначается агенту с наименьшей активной
  нагрузкой на момент начала прогона.
- **AC-6 (R4).** Если кандидатов больше, чем активных агентов-целей, назначения идут по
  кругу зафиксированного на старте порядка; после первого полного круга каждый активный
  агент получил не более чем на один канал больше любого другого.
- **AC-7 (R5).** При переносе канала от агента A агенту B: канал закрепляется за B в
  реестре, ссылка канала появляется в очереди вступления B, а строка канала у A
  удаляется.
- **AC-8 (R6).** Если по порядку round-robin канал должен уйти агенту A, но именно у A
  этот канал был забанен, канал получает следующий по порядку доступный агент, а не A.
- **AC-9 (R7).** В назначенное суточное время авторотация выполняется один раз,
  сканирует всех агентов платформы и не зависит от расписания задач конкретного агента.
