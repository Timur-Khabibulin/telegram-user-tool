# Этапы разработки

Последовательность работы над фичей. Каждый этап выполняется профильным
субагентом Claude Code или skill'ом.

## 1. Бизнес-требования

Уточнить и зафиксировать, **что** должна делать система: user stories, acceptance
criteria, ТЗ. Только в терминах поведения — без реализации (формул, метрик,
параметров, имён методов, алгоритма). Субагент: `bussines-system-analytic`.

## 2. Проектирование решения

Спроектировать, **как** система должна работать: высокоуровневая архитектура под
требования. Здесь принимаются решения уровня реализации — метрики, параметры,
алгоритм, рассмотренные альтернативы. Не пропускать этот этап: реализационные
решения рождаются здесь, а не в чате и не на этапе 1. Субагент: `software-architect`.

## 3. Аналитика для человека

Свести этапы 1–2 в design doc `docs/design/<feature>/<краткое-имя>-v1.md` по шаблону
`docs/design/_template.md`. Идёт **после** этапа 2. Уровень — поведение и архитектура
фичи, понятные человеку; имена методов, сигнатуры, арифметика вызовов и сверка с
кодом сюда не входят (это код и `decisions/`).

## 4. OpenSpec proposal

Завести change: proposal, tasks, delta specs. Skill: `openspec-propose`.

## 5. Реализация

Написать код по `coding-standards.md`; архитектурные решения фиксировать в
`decisions/`. Субагент: `typescript-senior-dev`. Skill: `openspec-apply-change`.

## 6. Review

Сверить результат с acceptance-критериями. Команда: `/code-review`.

## 7. Archive

Заархивировать change и обновить `openspec/specs/`. При изменении архитектуры
кода — обновить `architecture.md`; инфраструктуры — `operation.md`.
