# 0006. codex OAuth как основная LLM-модель

- Статус: заменено (2026-09-10) — новая реализация, change `llm-codex-primary-deepseek-fallback`
- Дата: 2026-05-31

> **Заменено.** Исходно (это ADR) codex был primary через `openai-oauth-provider` —
> он умер: с ~08.09.2026 codex-бэкенд отвергает все модели «неблагословлённых»
> клиентов (гейтинг по `originator`). Хронология: сначала мигрировали на DeepSeek
> (`migrate-llm-to-deepseek`), затем вернули codex-подписку как **primary** через
> живую библиотеку `@openai-oauth/ai-sdk` (модель `gpt-5.6-sol`, шлёт корректный
> originator), а DeepSeek оставили **fallback** на любую ошибку
> (`llm-codex-primary-deepseek-fallback`). Актуальное нормативное поведение —
> `openspec/specs/llm-layer/spec.md`. Ниже — исторический контекст исходного решения.

## Контекст
Скиллам нужна генерация текста и структурированного JSON. Хочется единого пула
лимита на всех агентов и устойчивости к сбоям модели.

## Решение
Основная модель — `gpt-5.4-mini` через codex-провайдер (`openai-oauth-provider`),
общий `auth.json` на всех агентов (`~/.openclaw/codex-auth/auth.json`,
`ensureFresh: true` — токен рефрешится автоматически). Предусмотрен fallback на
OpenAI (`ai-fallback`), сейчас закомментирован. `completeObject` валидирует JSON по
zod: нативный structured output → фидбэк-ретрай → точечное приведение типов.

## Последствия
- Один пул лимита ChatGPT Plus на всех агентов; токен сам обновляется.
- Трёхслойная стратегия структурированного вывода устойчива к «грязному» JSON.
- Минус: fallback пока выключен → при сбое codex генерация недоступна (см. backlog).

## Отвергнутые варианты
- Только прямой OpenAI API-ключ: отдельный учёт лимитов, нет общего пула.
- Доверять «верни валидный JSON» без слоёв валидации: ненадёжно на практике.
