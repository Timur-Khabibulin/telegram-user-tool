# 0005. SQLite на агента, тема на файл

- Статус: принято
- Дата: 2026-04-28

## Контекст
Нужно локальное состояние агента (каналы, кандидаты, треды, очереди, задачи,
прогоны, воронка) без отдельного сервера БД, с изоляцией между агентами.

## Решение
`better-sqlite3`, по базе на тему, все — в каталоге агента
`~/.openclaw/workspace-<agentId>/` (`tg-channels.db`, `tg-replies.db`,
`dm-threads.db`, `tg-join-queue.db`, `tasks.db`, у админ-агента — `funnel.db`).
Пути собраны в `src/core/config.ts`. Список агентов — по каталогам `workspace-*`.

## Последствия
- Простое, безсерверное состояние; естественная изоляция данных по агенту.
- Схемы создаются идемпотентно (`CREATE TABLE IF NOT EXISTS`).
- Минус: `better-sqlite3` — нативный модуль (требует совместимой сборки в окружении).
- Минус: нет общего стораджа между агентами (для воронки сознательно выбран один
  админ-агент-владелец `funnel.db`).

## Отвергнутые варианты
- Один общий серверный БД: избыточно для текущего масштаба, усложняет деплой.
- Реестр агентов отдельной таблицей: предпочли источник истины — каталоги workspace.
