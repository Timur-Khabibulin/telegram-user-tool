# 0004. Идемпотентность через ранний mark_as_read

- Статус: принято
- Дата: 2026-04-28

## Контекст
Прогон может упасть в середине (ошибка LLM, Telegram, сети). Нужно, чтобы на
следующем тике те же сообщения не обрабатывались повторно, без отдельной базы
истории обработанных сообщений.

## Решение
Вызывать `telegram_mark_as_read` сразу после `telegram_get_messages` — до любой
LLM-логики и отправки ответов.

## Последствия
- Процесс идемпотентен между запусками по построению; отдельная история не нужна.
- Минус: если прогон упал после mark_as_read, но до ответа, сообщение считается
  прочитанным и не будет переобработано — допустимый компромисс (ответ
  необязателен на каждое сообщение).

## Отвергнутые варианты
- Отдельная БД истории обработанных сообщений: лишняя сложность и состояние,
  которое надо синхронизировать.
