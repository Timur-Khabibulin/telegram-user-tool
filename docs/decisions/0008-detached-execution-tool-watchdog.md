# 0008. Detached-исполнение долгих операций вне per-tool-call watchdog

- Статус: принято
- Дата: 2026-09-20

## Контекст
Runtime агента (codex/OpenClaw) режет один вызов тула по watchdog ~90 s. Операции
дольше этого (reauth из tdata, автрегистрация, инвайт-ссылки по флоту, reauth-sweep)
не влезают — прогон убивается на середине, возможно частичное состояние.

## Решение
Логику выносим в чистую функцию (`src/features/<op>/run.ts`) + ops-скрипт
(`src/scripts/ops/<op>.ts`) и запускаем detached (`systemd-run`). Тул/скилл лишь
стартует job и сразу возвращает управление. Скрипт сам шлёт итог в Saved Messages
и держит собственный жёсткий таймаут (в detached watchdog'а, который снял бы зависший
процесс, нет). Тот же код доступен тонким plugin-тулом для коротких вызовов.

## Последствия
- Операции любой длительности выполняются целиком; наблюдаемость и остановка —
  через systemd.
- Отчёт приходит асинхронно, а не ответом тула.
- Каждый ops-скрипт обязан иметь внутренний таймаут — иначе зависший процесс не снять.

## Отвергнутые варианты
- Синхронный вызов тула — не влезает в ~90 s.
- Ручной супервизор (spawn + PID-файл) — дублирует systemd, гонки на lock/PID.
