# 0002. Один диспетчер на агента, задачи последовательно

- Статус: принято
- Дата: 2026-05-24

## Контекст
У агента несколько задач (monitor, dm-send, dm-replies, warmup, join-queue) с
разными периодами. Нужна точка, которая решает, что назрело, и исполняет это, не
создавая гонок за одной Telegram-сессией.

## Решение
Один процесс-диспетчер на прогон агента (`tsx dispatcher.ts --agent <id>`),
запускается heartbeat-таймером (`tg-agent@.timer`, каждые 10 минут). Он выбирает
задачи `enabled=1 AND nextRun<=now` и выполняет их **последовательно** на одном
клиенте Telegram.

## Последствия
- Точка сериализации одна → параллельных задач внутри агента нет по построению,
  внешний лок не нужен.
- `nextRun` сдвигается всегда (и при success, и при error) — задача не застревает.
- Минус: задачи одного агента не идут параллельно (для текущих нагрузок приемлемо).

## Отвергнутые варианты
- Отдельный процесс/таймер на каждую задачу: больше юнитов и риск гонок за сессией.
- Внутренний пул с локами: лишняя сложность при единственной точке сериализации.
