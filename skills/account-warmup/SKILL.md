# Account Warmup — Прогрев аккаунта

## Цель

Имитировать активность живого пользователя: читать непрочитанные чаты и помечать их прочитанными. По итогам прогона дополнительно проанализировать темы накопленных сообщений и **один раз** ответить на самое подходящее по личности агента сообщение. Без записи в БД.

---

## Алгоритм

### Шаг 1 — Загрузить конфигурацию аккаунта

```
tg_load_account(
  agentId: <agentId из раздела Runtime системного промпта>
)
```

Если инструмент вернул ошибку — **завершить выполнение**.

---

### Шаг 2 — Получить диалоги с непрочитанными сообщениями

```
telegram_get_dialogs()
```

Возвращает список чатов с `unreadCount > 0`. Если список пустой — **завершить выполнение**.

---

### Шаг 3 — Выбрать случайные 15 чатов

Случайно перемешать полученный список. Взять первые **15** (или меньше, если чатов меньше 15).

---

### Шаг 4 — Обработать каждый чат

Завести **пустой буфер кандидатов** `candidates = []` — в него будем складывать сообщения из всех чатов для последующего анализа в шаге 5.

Для **каждого** чата из выборки выполнить:

#### 4.1 Получить сообщения

```
telegram_get_messages(
  chatId: <chatId>,
  minId:  <readInboxMaxId>,
  limit:  50
)
```

При ошибке **FLOOD_WAIT_X** — подождать X секунд, повторить один раз. Если ошибка повторилась — **завершить весь прогон**.

При любой другой ошибке — **пропустить этот чат**, перейти к следующему.

Если сообщений нет — **пропустить этот чат**, перейти к следующему.

Добавить полученные сообщения в `candidates` — каждое в виде `{ chatId, chatTitle, id, fromName, text }`.

#### 4.2 Пометить как прочитанные

Вызвать **сразу** после получения сообщений:

```
telegram_mark_as_read(
  chatId: <chatId>,
  maxId:  max(message.id из шага 4.1)
)
```

При ошибке **FLOOD_WAIT_X** — подождать X секунд, повторить один раз. Если ошибка повторилась — **завершить весь прогон**.

При любой другой ошибке — **пропустить**, перейти к следующему чату.

#### 4.3 Пауза

Подождать **10–30 секунд** перед переходом к следующему чату.

---

### Шаг 5 — Определить темы обсуждения (LLM)

Если `candidates` пуст — **завершить выполнение**.

Иначе выполнить **один** LLM-вызов на весь буфер:

```
Перечисли основные темы обсуждения в этих сообщениях.
Ответь кратко — список тем без пояснений.

Сообщения:
<для каждого c из candidates:>
- [<c.chatTitle>] <c.fromName>: <c.text>
```

Если темы не соотносятся с личностью агента — **завершить выполнение**.

---

### Шаг 6 — Выбрать одно релевантное сообщение (LLM)

Выполнить **один** LLM-вызов на весь буфер:

```
Из списка ниже выбери ОДНО сообщение, на которое тебе есть что ответить
исходя из своей личности и экспертизы. Выбери самое подходящее во всём батче.

Верни ТОЛЬКО JSON-объект:
{ "chatId": <chatId>, "id": <message_id>, "text": "<текст сообщения>" }

Если подходящих сообщений нет — верни пустой объект {}.

Сообщения:
<для каждого c из candidates:>
- chatId=<c.chatId>, id=<c.id>, <c.fromName>: <c.text>
```

Если результат — пустой объект `{}` — **завершить выполнение**.

---

### Шаг 7 — Сгенерировать ответ (LLM)

```
Напиши ответ на следующее сообщение в чате Telegram.
До 3 предложений, естественно, в твоём стиле.

Сообщение: "<text из шага 6>"
```

---

### Шаг 8 — Отправить ответ

```
telegram_reply_to_message(
  chatId:           <chatId из шага 6>,
  replyToMessageId: <id из шага 6>,
  text:             <ответ из шага 7>,
  originalText:     <text из шага 6>
)
```

При ошибке **FLOOD_WAIT_X** — подождать X секунд, повторить один раз. Если ошибка повторилась — **завершить выполнение** без ответа.

При любой другой ошибке — **завершить выполнение** без ответа.

---

## Ограничения

- Не более 15 чатов за один прогон
- Не более **одного** ответа за прогон (после шага 8 — выход)
- При повторном FLOOD_WAIT — прервать прогон целиком
