# Account Warmup — Прогрев аккаунта

## Цель

Имитировать активность живого пользователя: читать непрочитанные чаты и помечать их прочитанными. Без анализа сообщений, без ответов, без записи в БД.

---

## Алгоритм

### Шаг 1 — Загрузить конфигурацию аккаунта

```
tg_load_account(
  agentId: <agentId из раздела Runtime системного промпта>
)
```

Если инструмент вернул ошибку — **завершить выполнение**.

---

### Шаг 2 — Получить диалоги с непрочитанными сообщениями

```
telegram_get_dialogs()
```

Возвращает список чатов с `unreadCount > 0`. Если список пустой — **завершить выполнение**.

---

### Шаг 3 — Выбрать случайные 15 чатов

Случайно перемешать полученный список. Взять первые **15** (или меньше, если чатов меньше 15).

---

### Шаг 4 — Обработать каждый чат

Для **каждого** чата из выборки выполнить:

#### 4.1 Получить сообщения

```
telegram_get_messages(
  chatId: <chatId>,
  minId:  <readInboxMaxId>,
  limit:  50
)
```

При ошибке **FLOOD_WAIT_X** — подождать X секунд, повторить один раз. Если ошибка повторилась — **завершить весь прогон**.

При любой другой ошибке — **пропустить этот чат**, перейти к следующему.

Если сообщений нет — **пропустить этот чат**, перейти к следующему.

#### 4.2 Пометить как прочитанные

Вызвать **сразу** после получения сообщений:

```
telegram_mark_as_read(
  chatId: <chatId>,
  maxId:  max(message.id из шага 4.1)
)
```

При ошибке **FLOOD_WAIT_X** — подождать X секунд, повторить один раз. Если ошибка повторилась — **завершить весь прогон**.

При любой другой ошибке — **пропустить**, перейти к следующему чату.

#### 4.3 Пауза

Подождать **10–30 секунд** перед переходом к следующему чату.

---

## Ограничения

- Не более 15 чатов за один прогон
- Никаких LLM-вызовов, никаких ответов, никакой записи в БД
- При повторном FLOOD_WAIT — прервать прогон целиком
