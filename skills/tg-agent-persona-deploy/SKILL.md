# tg-agent-persona-deploy — развёртывание агентов из пула под персону (фаза 2)

Скилл собирает параметры и запускает прогон отсоединённым фоновым процессом,
отчёт приходит в Saved Messages получателя отчётов. Фаза 2 потребляет обезличенные
пул-аккаунты (произведённые фазой 1 `tg-agent-pool-provision`) и применяет к ним
персону через их собственную агентскую сессию.

---

## Шаг 1 — Собрать параметры

> Для развёртывания агентов под персону укажи:
>
> • **personName** — имя персоны (шаблон в `~/.openclaw/personas/<personName>/` на ВПС)
>
> • **count** — сколько агентов создать (M)

Пул-аккаунты берутся автоматически: старейшие первыми, невалидные пропускаются.
Номер агента `agent<N>` выдаётся автоматически (max присутствующих + 1), безопасно
при параллельных прогонах.

---

## Шаг 2 — Запустить прогон (в фоне, detached — ADR 0008)

```
systemd-run \
  --unit="tg-persona-deploy-$(date +%s)" \
  --property=Type=oneshot \
  --property=WorkingDirectory=/root/openclaw-plugins/telegram-user-tool \
  --property=EnvironmentFile=-/root/.openclaw/secrets.env \
  --collect \
  /root/openclaw-plugins/telegram-user-tool/node_modules/.bin/tsx \
    src/scripts/ops/tg-agent-persona-deploy.ts \
    --person-name <имя персоны> \
    --count <сколько агентов>
```

Скрипт берёт до `count` пригодных пул-аккаунтов (старейших), на каждом через его
агентскую сессию задаёт username/профиль/фото, создаёт публичный канал персоны с
постом и закрепом, вставляет инвайт-ссылку в общий приватный канал воронки, затем
атомарно переводит в `workspace-agent<N>`. Ops-скрипт держит собственный жёсткий
таймаут.

---

## Шаг 3 — Подтвердить запуск

`systemd-run` возвращает управление сразу. Отчёт придёт в Saved Messages
(`REPORT_AGENT_ID`) и содержит итоговую строку «запрошено M, создано X» и статус
каждого аккаунта:
- `done` — персона применена, `workspace-agent<N>` создан
- `setup_failed` — ошибка Telegram API при применении персоны (аккаунт остаётся в
  невидимом `workspace-agent<N>.incoming`, рабочим контуром не подхватывается)
- `account_invalid` — пул-аккаунт оказался нерабочим при подключении → карантин,
  добор из следующего

При нехватке пула до `count` — частичный успех (создаётся сколько получилось),
нехватка сообщается в отчёте. Пул пополняется скиллом `tg-agent-pool-provision`.

Ход прогона: `journalctl -u tg-persona-deploy-<...> -f`.
