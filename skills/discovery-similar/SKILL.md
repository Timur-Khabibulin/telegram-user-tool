# Channel Discovery (similar) — поиск похожих каналов и постановка в очередь

> **DEPRECATED.** Скилл выведен из эксплуатации, использовать не нужно.

Операторский скилл: силами заданных агентов-**искателей** находит похожие каналы через
нативные рекомендации Telegram, отбирает по подписчикам и **распределяет находки по всем
агентам платформы без пересечений**.

---

## Шаг 1 — Собрать параметры

При вызове скилла **одним сообщением** запроси у оператора, что нужно:

> Чтобы найти похожие каналы, мне нужно:
>
> • **min_subscribers** — минимум подписчиков у канала.
>
> • **target** — сколько новых каналов набрать **каждому агенту платформы**. Всего соберём
>   `target × N`, где N — число агентов платформы, и распределим находки по всем агентам.
>
> • **агенты-искатели** — чьи аккаунты ведут обход (их сессии и каналы — отправные точки).
>
> • **theme** — тематика прогона (единая на все агенты). По ней каждый кандидат
>   оценивается на релевантность; нерелевантные в очередь не попадают.
>
> • **min_avg_views** — минимальный средний просмотр на пост (`minAvgViews`):
>   **обязательный** параметр без дефолта, задайте явно, исходя из вашей нишы/языка.
>   Канал с вовлечённостью ниже этого порога отсеивается до тематической оценки.
>
> • *(необязательно)* порог релевантности темы (0..1) — кандидат проходит при оценке
>   строго выше порога; по умолчанию 0.5.
>
> • *(необязательно)* число последних постов канала (`postsCount`) — общее окно для
>   оценки вовлечённости и темы; по умолчанию 20 (минимум 3).
>
> • *(необязательно)* минимальный ER (engagement rate, `minEngagementRate`) — по
>   умолчанию 0.1.

Зафиксируй `min_subscribers`, `target`, `theme`, `min_avg_views` и список искателей
(`agents`). Если что-то не указано — переспроси только недостающее (искатели, тема и
`minAvgViews` обязательны).

> Порядок гейтов кандидата: подписчики → группа обсуждения → ER/средний просмотр на пост →
> тема (LLM). Вовлечённость отправных точек (seed-каналов) оценивается по тому же правилу
> окна — последние посты минус 2 самых свежих, медиана просмотров / подписчики.

## Шаг 2 — Запустить обход

```
tg_discovery_similar_run(
  minSubscribers: <min_subscribers>,
  target:         <target>,
  agents:         <список искателей>,
  theme:          <тема прогона>,
  minAvgViews:    <порог среднего просмотра на пост>
  [, minTopicScore: <порог 0..1>]
  [, postsCount: <число постов>]
  [, minEngagementRate: <порог ER>]
)
```

## Шаг 3 — Показать отчёт

Выведи оператору поле `report` из ответа: сколько всего каналов собрано против цели
`target × N` и чем закончился сбор — достигнута цель (`🎯 цель достигнута`) или граф
искателей исчерпан; сколько кандидатов отсеяно по причинам (нет группы / низкая
вовлечённость — ER или средний просмотр на пост ниже порога / тема ниже порога / мало
подписчиков); какие искатели были прерваны ограничениями (`⚠️ … FLOOD_WAIT`); и
распределение новых каналов по агентам платформы.

Если искатель прерван по FLOOD_WAIT — можно повторить прогон позже (счётчик не
накапливается между запусками). Напомни, что вступление произойдёт не сейчас, а на
ближайшем тике таймера `join-queue` каждого агента.
