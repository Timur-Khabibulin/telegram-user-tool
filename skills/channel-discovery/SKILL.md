# Channel Discovery — поиск каналов и постановка в очередь вступления

> **DEPRECATED.** Скилл выведен из эксплуатации, использовать не нужно.

Операторский скилл: по теме находит новые каналы в агрегаторах, отбирает по качеству и раскладывает по агентам **без пересечений**

---

## Шаг 1 — Первое сообщение: собрать данные

При вызове скилла **сразу, одним сообщением** перечисли оператору, что нужно для поиска:

> Чтобы найти каналы, мне нужно от тебя:
> 
> • **Сфера/тема** — по чему искать (например «психология»). Ключевые слова предложу сам, ты уточнишь.
> 
> • **N** — сколько новых каналов набрать за прогон (на весь прогон, не на агента).
> 
> • **min_subscribers** — минимум подписчиков у канала.
> 
> • **min_avg_post_reach** *(необязательно)* — минимальный средний охват публикации по TGStat. Каналы с охватом ниже порога, без данных TGStat или без tgId отсеиваются. Внимание: новые каналы с коротким историческим окном могут иметь `avg_post_reach = 0` и будут отсеяны при любом ненулевом пороге.
> 
> • **avg_reach_agent** *(необязательно)* — agentId аккаунта для расчёта среднего охвата вручную через MTProto, когда TGStat не вернул данные (`channels/stat` недоступен или `tgId` отсутствует). Без него при ошибке TGStat кандидат отсеивается (fail-closed). Указывать только если задан `min_avg_post_reach`.

Зафиксировать из ответа `сфера`, `N`, `min_subscribers` и опционально `min_avg_post_reach`. Если оператор указал
не всё — спросить **только недостающее**, не переспрашивая уже данное.

## Шаг 2 — Предложить ключевые слова

По названной сфере предложить список **ключевых слов** для поиска (это твоя генерация —
синонимы, смежные темы, формулировки, по которым реально называют каналы). Показать
список оператору и попросить уточнить: что оставить, что убрать, что добавить.
Зафиксировать согласованный список `keywords`.

## Шаг 3 — Запустить прогон

```
tg_discovery_run(
  keywords:          <согласованный список>,
  n:                 <N>,
  minSubscribers:    <min_subscribers>,
  minAvgPostReach:   <min_avg_post_reach>   // если задан оператором, иначе опустить
  avgReachAgentId:   <avg_reach_agent>      // если задан оператором, иначе опустить
)
```

По умолчанию раскладка идёт на **всех** агентов (`listAgentIds()`) и реестр —
у админ-агента; задавать `agents` / `adminAgentId` нужно только если оператор просит
ограничить. Инструмент ищет по словам, отсекает по подписчикам, дедуплицирует
против реестра, раскладывает round-robin, пишет в реестр и в `join_queue` агентов.

## Шаг 4 — Показать отчёт

Вывести оператору поле `report` из ответа: сколько каналов найдено и распределено по
агентам и достигнут ли `N`. Если `exhausted: true` (нашли меньше `N`, пространство слов
исчерпано) — предложить оператору **расширить ключевые слова** (Шаг 2) или **снизить
порог** `min_subscribers` и при желании запустить ещё раз.

Напомнить, что вступление произойдёт не сейчас, а на ближайшем тике таймера `join-queue`
каждого агента.
