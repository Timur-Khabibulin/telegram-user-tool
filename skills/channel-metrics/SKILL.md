# Channel Metrics — метрики произвольного списка каналов

Операторский скилл: по списку ссылок на каналы одной сессией агента считает
подписчиков, средний охват последних постов, открытость комментариев и тип
канала (broadcast/мегагруппа). По желанию — ещё и нишу/тематику каждого канала
одним LLM-вызовом.

---

## Шаг 1 — Собрать параметры

Запроси у оператора, что нужно:

> Чтобы собрать метрики по каналам, мне нужно:
>
> • **ссылки** — список каналов (t.me/username или полные ссылки).
>
> • **агент** — чьей сессией сканировать.
>
> *(необязательно)* нужна ли **ниша/тематика** каждого канала (через LLM) —
> по умолчанию не считается, только метрики.

Зафиксируй `links` (непустой список), `agentId`. Если оператор просит «темы»,
«ниши», «о чём каналы» — включи `withNiche: true`.

## Шаг 2 — Запустить сбор метрик

```
tg_channel_metrics(
  agentId:   <агент>,
  links:     [<ссылка>, ...]
  [, withNiche: true]
)
```

Прогон идёт последовательно по ссылкам на сессии одного агента, с паузами
между запросами (бережём сессию). CSV пишется по ходу прогона в `reports/`
агента и после завершения отправляется в его Saved Messages.

Если прогон остановился по `FLOOD_WAIT` (`stoppedByFlood: true` в ответе) —
запусти инструмент повторно с **тем же `runId`** из ответа: уже обработанные
ссылки будут пропущены, продолжится с места остановки.

## Шаг 3 — Сообщить оператору итог

По завершении сообщить:

- сколько ссылок обработано (`done`) и сколько пропущено как уже обработанные
  в этом прогоне (`skipped`);
- что CSV отправлен в Saved Messages агента;
- если `stoppedByFlood: true` — что часть списка не обработана из-за
  FLOOD_WAIT, и как продолжить (повторный вызов с тем же `runId`).

Колонки CSV: `link, subs_count, avg_views, comments_open, is_broadcast, error`
(без `withNiche`); с `withNiche` дополнительно `title, niche` перед `error`.

---

## Ограничения и заметки

- Приватные ссылки (без публичного username) не резолвятся через MTProto —
  попадают в CSV с пустыми метриками и ошибкой «резолв по username
  невозможен».
- `withNiche` не делает второго похода в Telegram — LLM получает уже
  полученные для метрик title/описание/посты.
- Тот же прогон доступен из командной строки (для больших списков без
  ограничения на размер ответа инструмента):
  `tsx src/scripts/ops/channel-metrics.ts --input links.csv --output metrics.csv --agent <agentId> [--with-niche]`.
  CLI и скилл используют одну и ту же логику (`core/channel-metrics/run.ts`) —
  поведение идентично.
