# Telegram agent create (v2)

> **DEPRECATED.** Заменён на `tg-agent-autoregistration` (массовая
> автоматическая регистрация из tdata-сессий). Этот скилл оставлен для
> справки, новых агентов через него создавать не нужно.

## Чек-лист подготовки

Перед запуском убедись, что пользователь выполнил всё вручную:

- [ ] Настроен эмулятор, TG-аккаунт зарегистрирован (номер телефона активен в Telegram)
- [ ] Получены API-ключи на https://my.telegram.org/auth (понадобятся позже, на Шаге 3 — после
      того как прокси уже подтверждён)

Прокси создавать вручную не нужно — система создаёт его первым шагом (Шаги 1-2) и выдаёт
человеку. Вход в аккаунт через официальное Telegram-приложение делается **именно через этот
выданный прокси** (Шаг 2.5) — это единственная проверка, что прокси рабочий, и одновременно
это гарантирует, что у ручной сессии в приложении и у будущей автоматизированной сессии бота
(Шаг 5) один и тот же IP/гео.мо

---

## Шаг 1 — Запросить данные для подбора прокси

Сообщи пользователю, что нужны следующие данные, и жди одного ответа:

```
Для подбора прокси нужны следующие данные — скинь их одним блоком:

- agentName    — имя агента на английском (используется как идентификатор)
- maxAttempts  — (опционально) сколько кандидатов прокси перебирать, по умолчанию 5
```

Запомни значения. Остальные данные аккаунта (`apiId`, `apiHash`, `telegram_user_id`,
`deviceModel`, `phoneNumber`, `sessionString`) понадобятся позже, на Шаге 3 — после того как
прокси будет подтверждён.

---

## Шаг 1.1 — Выбрать страну прокси

**СТОП.** Спроси у пользователя:

```
Хочешь сразу указать код страны прокси текстом, или выбрать из списка доступных стран?
```

Источник кандидатов (`/proxy/search`) фильтруется только по стране — региона/города здесь
больше нет (mobile-proxy-unique-exit-ip).

### Вариант A — готовое значение

Юзер называет `countryCode` текстом. Запомнить и перейти к Шагу 2.

### Вариант B — выбор из списка

```bash
cd ~/.openclaw/extensions/telegram-user-tool && ./node_modules/.bin/tsx \
  src/scripts/provision-proxy-for-new-agent.ts --list-countries
```

Показать список (`код <TAB> название`), спросить пользователя, какую страну выбрать. Запомнить
`countryCode`.

Перейти к Шагу 2.

---

## Шаг 2 — Создать кандидата прокси

**СТОП.** Напиши пользователю короткое сообщение и продолжай дальше:

```
Создаю кандидата мобильного прокси (попытка <N>/<maxAttempts>)...
```

`<N>` — номер попытки, начинается с 1 и увеличивается на 1 при каждом возврате на этот шаг из
Шага 2.5 (неудачная ручная проверка). Заведи (в контексте разговора, не в файле) список
`rejectedLogins` — изначально пустой; на каждый возврат из Шага 2.5 добавляй в него
`username` отвергнутого кандидата.

Вызвать:

```bash
cd ~/.openclaw/extensions/telegram-user-tool && ./node_modules/.bin/tsx \
  src/scripts/provision-proxy-for-new-agent.ts \
  --create-candidate \
  --agent-id <agentName> \
  --country <countryCode> \
  --exclude "<rejectedLogins через запятую, опустить флаг если список пуст>"
```

Скрипт печатает одну JSON-строку с данными кандидата — `{"host":...,"port":...,"username":...,
"password":...,"countryCode":...}`, либо `{"ok":false,"poolExhausted":true}`, если свободных
прокси для страны не осталось (см. Шаг 2.5, «Если пул исчерпан»). Запомнить значения кандидата.
Скрипт НЕ проверяет подключение — переходи сразу к Шагу 2.5.

---

## Шаг 2.5 — Выдать прокси человеку и дождаться ручной проверки

**СТОП.** Напиши пользователю созданный прокси и жди ответа. Не переходи к Шагу 3 без ответа:

```
Прокси создан:
  host:     <proxy.host>
  port:     <proxy.port>
  username: <proxy.username>
  password: <proxy.password>

Зайди в аккаунт через официальное Telegram-приложение, используя ИМЕННО этот прокси.
Напиши, когда войдёшь — или что не получилось.
```

### Если вход не удался

**СТОП.** Напиши пользователю:

```
Понял, кандидат не подошёл. Беру следующий (попытка <N+1>/<maxAttempts>).
```

Добавить `username` этого кандидата в `rejectedLogins` (Шаг 2) — на asocks удалять нечего, это
существующий ресурс аккаунта, не созданный этим прогоном.

Если `<N+1>` не превышает `maxAttempts` — вернуться к Шагу 2 с увеличенным номером попытки.

Если `maxAttempts` попыток исчерпаны:

**СТОП.** Напиши пользователю:

```
Не удалось подобрать рабочий прокси за <maxAttempts> попыток в стране <countryCode>.
Попробовать другую страну (вернуться к Шагу 1.1), увеличить число попыток, или остановиться?
```

Ждать ответа. Если пользователь соглашается — повторить с новой страной или новым
`maxAttempts` (счётчик попыток и `rejectedLogins` сбросить). Если отказывается — завершить
выполнение.

### Если пул исчерпан

**СТОП.** Если Шаг 2 вернул `{"ok":false,"poolExhausted":true}` (свободных мобильных прокси для
страны не осталось, до исчерпания `maxAttempts`), напиши пользователю:

```
Свободных мобильных прокси для страны <countryCode> не осталось.
Попробовать другую страну (вернуться к Шагу 1.1) или остановиться?
```

Ждать ответа. Если пользователь соглашается — вернуться к Шагу 1.1 с новой страной
(`rejectedLogins` сбросить). Если отказывается — завершить выполнение.

### Если вход удался

Прокси подтверждён. Перейти к Шагу 3.

---

## Шаг 3 — Запросить остальные данные аккаунта

**СТОП.** Напиши пользователю короткое сообщение и продолжай дальше:

```
Прокси подтверждён.
```

Сообщи пользователю, что нужны следующие данные, и жди одного ответа:

```
Теперь нужны данные аккаунта — скинь их одним блоком:

- telegram_user_id  — ID TG-аккаунта агента (узнать в @userinfobot)
- apiId             — API ID с my.telegram.org
- apiHash           — API Hash с my.telegram.org
- deviceModel       — модель устройства (например: Samsung Galaxy S23)
- phoneNumber       — номер телефона аккаунта агента (формат +79001234567)
- sessionString     — (опционально) готовая сессия. Если есть — авторизация (Шаг 5) пропускается
```

Запомни все полученные значения — они используются на следующих шагах вместе с прокси,
подтверждённым на Шаге 2.5.

Перейти к Шагу 4.

---

## Шаг 4 — Создать структуру агента

**СТОП.** Напиши пользователю короткое сообщение и продолжай дальше:

```
Создаю структуру агента.
```

Проверить, не существует ли уже `~/.openclaw/workspace-<agentName>/tg-account.json` — если
существует, **СТОП**, сообщить пользователю, что агент с таким именем уже создан, и остановиться
(не перезаписывать существующего агента).

Иначе создать каталог:

```bash
mkdir -p ~/.openclaw/workspace-<agentName>/
```

Это единственное действие на этом шаге — агент **не регистрируется** в OpenClaw (`agents.list`),
не добавляется биндинг, не создаётся `agentDir`. См. чек-лист подготовки.

Перейти к шагу 4.1

### 4.1 Промежуточный статус

**СТОП.** Напиши пользователю короткое сообщение и продолжай дальше:

```
Каталог агента создан. Перехожу к авторизации Telegram-сессии.
```

Если в Шаге 3 был передан `sessionString` — текст замени на:

```
Каталог агента создан. Перехожу к записи tg-account.json.
```

Перейти к шагу 4.2

---

## 4.2 Развилка после Шага 4.1

Если в данных из Шага 3 присутствует `sessionString` — **пропустить Шаг 5** и перейти сразу к
Шагу 6, используя эту строку как `sessionString`.

Если `sessionString` не был передан — выполнить Шаг 5.

---

## Шаг 5 — Получить sessionString

### 5.1 Отправить код

**СТОП.** Напиши пользователю короткое сообщение и продолжай дальше:

```
Отправляю код на номер <phoneNumber>. Инструмент сделает до 3 попыток по 30 секунд каждая.
```

Вызвать, используя прокси, подтверждённый на Шаге 2.5:

```
tg_auth_send_code(
  apiId:       <apiId>,
  apiHash:     <apiHash>,
  phoneNumber: <phoneNumber>,
  proxy: {
    type:     "socks5",
    host:     <proxy.host из Шага 2.5>,
    port:     <proxy.port из Шага 2.5>,
    username: <proxy.username из Шага 2.5>,
    password: <proxy.password из Шага 2.5>
  }
)
```

Если ответ содержит поле `error`:

**СТОП.** Напиши пользователю:

```
Не удалось отправить код. Ошибка: <error из ответа>

Повторить попытку?
```

Ждать ответа. Если пользователь соглашается — повторить вызов шаг 5.1. Если отказывается —
завершить выполнение.

Если успех — сохранить `phoneCodeHash` из ответа и перейти к шагу 5.2.

### 5.2 Запросить код у пользователя

**СТОП.** Напиши пользователю следующее сообщение и жди ответа. Не переходи к шагу 5.3 до
получения кода:

```
Код отправлен в Telegram на номер <phoneNumber>.
Пришли код из Telegram.
Если на аккаунте включён 2FA — пришли также пароль.
```

### 5.3 Войти в аккаунт

Перед вызовом напиши пользователю:

```
Выполняю вход. Инструмент сделает до 3 попыток по 60 секунд каждая.
```

Вызвать:

```
tg_auth_sign_in(
  phoneNumber:   <phoneNumber>,
  phoneCodeHash: <phoneCodeHash из шага 5.1>,
  phoneCode:     <код от пользователя>,
  password:      <2FA пароль, если был прислан>
)
```

Если ответ содержит поле `error`:

**СТОП.** Напиши пользователю:

```
Не удалось войти в аккаунт. Ошибка: <error из ответа>

Повторить попытку? Если код уже истёк — нужно будет запросить новый (вернуться к шагу 5.1).
```

Ждать ответа пользователя:
- Если соглашается повторить с тем же кодом — повторить вызов `tg_auth_sign_in`
- Если код истёк или пользователь хочет новый — вернуться к шагу 5.1
- Если отказывается — завершить выполнение

Если успех — сохранить `sessionString` из ответа и перейти к шагу 6.

---

## Шаг 6 — Создать tg-account.json

Записать файл `~/.openclaw/workspace-<agentName>/tg-account.json` со всеми заполненными
значениями (прокси — тот же, что подтверждён на Шаге 2.5):

```json
{
  "accountId": "<telegram_user_id>",
  "apiId": <apiId>,
  "apiHash": "<apiHash>",
  "sessionString": "<sessionString из шага 3 (если был передан) или из шага 5.3>",

  "device": {
    "deviceModel": "<deviceModel>",
    "systemVersion": "Android 14",
    "appVersion": "10.3.2",
    "langCode": "ru",
    "systemLangCode": "ru"
  },

  "proxy": {
    "type": "socks5",
    "host": "<proxy.host из Шага 2.5>",
    "port": <proxy.port из Шага 2.5>,
    "username": "<proxy.username из Шага 2.5>",
    "password": "<proxy.password из Шага 2.5>",
    "countryCode": "<proxy.countryCode из Шага 2.5>"
  }
}
```

Перейти к шагу 7

---

## Шаг 7 — Персона (SOUL.md)

Все агенты платформы используют одну и ту же персону — эталон лежит в
`~/.openclaw/workspace-agent1/SOUL.md`. По умолчанию просто скопировать его, **не запрашивая
текст у пользователя**:

```bash
cp ~/.openclaw/workspace-agent1/SOUL.md ~/.openclaw/workspace-<agentName>/SOUL.md
```

Если пользователь явно попросил другую персону для этого агента — тогда (и только тогда)
спросить текст `SOUL.md` и записать его вместо копирования эталона.

Перейти к шагу 8

---

## Шаг 8 — Проверка установки

```bash
bash ~/.openclaw/workspace/skills/tg-agent-create-v2/scripts/verify-agent.sh '<agentName>'
```

Скрипт проверяет только то, что реально создаётся этим процессом: существование каталога
workspace, валидность `tg-account.json`, непустоту `SOUL.md`. Проверок регистрации в OpenClaw
здесь нет — агент её не получает.

**СТОП.** Обязательно скопируй вывод скрипта в сообщение пользователю как есть. Не прерывай
скилл даже при FAIL — переходи к Шагу 9.

---

## Шаг 9 — Итог

**СТОП.** Обязательно напиши пользователю финальное сообщение:

```
Агент <agentName> готов.
- TG-аккаунт: <telegram_user_id>
- Workspace: ~/.openclaw/workspace-<agentName>
- Прокси: <proxy.host>:<proxy.port> (<countryCode>)

Агент не зарегистрирован как разговорная сущность OpenClaw (agents.list/agentsBot) — по
дизайну v2, это не требуется для работы через диспетчер.

Перед работой с агентом не забудь перезапустить gateway командой `openclaw gateway restart`
```
