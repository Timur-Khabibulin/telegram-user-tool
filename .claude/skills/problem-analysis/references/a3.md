# A3 — one-page documentation for Phase 5 (Output)

Purpose: render the diagnosis on a single structured page (Toyota A3). This skill
**diagnoses only** — so fill boxes 1–6 fully and leave **Countermeasures / Plan /
Follow-up (boxes 7–9) as a downstream hand-off** (they belong to a solution step,
not to diagnosis). Use A3 when a reviewer or another team needs the whole story
at a glance.

## The A3 structure

```
┌─ TITLE: <one line naming the problem> ─────────────────────────────────────┐
│ Owner: <who>            Date: <date>                                        │
├─ LEFT (diagnosis — fill now) ──────────┬─ RIGHT (solution — downstream) ────┤
│ 1. BACKGROUND                          │ 7. COUNTERMEASURES   [downstream]  │
│    Why this matters; context.          │    (candidate fixes — not here)    │
│                                        │                                    │
│ 2. CURRENT CONDITION                   │ 8. PLAN              [downstream]  │
│    Observable gap: expected vs actual, │    who / what / when               │
│    magnitude, boundary (Is/Is-Not).    │                                    │
│    Evidence, data, a chart if useful.  │ 9. FOLLOW-UP         [downstream]  │
│                                        │    how recurrence is verified      │
│ 3. GOAL / TARGET                       │                                    │
│    The condition that = resolved.      │                                    │
│                                        │                                    │
│ 4. ROOT-CAUSE ANALYSIS                 │                                    │
│    Fishbone candidates → 5 Whys chain  │                                    │
│    → validated root condition + the    │                                    │
│    readiness score (X/4).              │                                    │
│                                        │                                    │
│ 5. HYPOTHESES EVALUATED                │                                    │
│    confirmed / ruled out + evidence.   │                                    │
│                                        │                                    │
│ 6. REMAINING UNCERTAINTY               │                                    │
│    what would make this diagnosis wrong│                                    │
└────────────────────────────────────────┴────────────────────────────────────┘
```

## Fill order

1–3 frame the problem (reuse Phase 1 output). **4** embeds the method pipeline:
Fishbone (`fishbone.md`) for candidates → 5 Whys (`5-whys.md`) for the chain →
root condition + the four-question readiness score from Phase 4. **5–6** carry the
ruled-out hypotheses and the uncertainty. Boxes **7–9 stay as placeholders**
marked `[downstream]` — do not invent fixes here; that breaks the scope boundary.

## Rules

- Everything on the left is an **observable condition + evidence**, never an
  absence and never a solution.
- One page. If it doesn't fit, the problem isn't singular — split it (Phase 1).
- The A3 is a view over the same diagnosis as the Phase-5 report, not new content.
