---
name: mobile-proxy-provision
description: Automatically provision a working mobile proxy (asocks.com) for one or more agents stuck on the MTProto connect-timeout issue. Use when the user wants to fix/replace a broken mobile proxy for an agent, or provision proxies for a list of agents.
---

Автоматически подбирает рабочий мобильный прокси для агента(ов) из существующего инвентаря
asocks.com (`GET /proxy/search`, mobile-proxy-unique-exit-ip): берёт следующего ещё не занятого
другим агентом кандидата → проверяет реальным MTProto-подключением (сессией самого агента) →
если не работает, берёт следующего — до заданного числа попыток или до исчерпания пула страны.
Кандидаты не создаются и не удаляются на стороне asocks — это готовый инвентарь аккаунта, не
новый ресурс. Выполняется скриптом на VPS (см. skill `vps` — та же
`ssh -i ~/.ssh/vps_key root@<VPS_HOST>`).

## Когда использовать

Агент(ы) стабильно падают с `ConnectTimeoutError`/`Client not connected` в
`journalctl -u tg-agent@<agentId>`, либо у нескольких агентов совпадает прокси (`host+port+
username+password` одинаковые — коллизия exit IP, см. `openspec/changes/mobile-proxy-unique-
exit-ip/design.md`).

## Входные параметры (спросить, если не даны)

| Параметр | Обязателен | По умолчанию |
|---|---|---|
| Список `agentId` | да | — |
| Страна | нет | из `tg-account.json` агента (`proxy.countryCode`), если там уже есть с прошлого подбора |
| Макс. попыток на агента | нет | 5 |

Страну нужно спрашивать у пользователя явно только если у агента ещё нет сохранённой страны
(агент создан/чинился до появления этого механизма) — тогда без страны скрипт не сможет
подобрать кандидата (регион неизвестен ни из флага, ни из конфига). Если юзер прямо просит
сменить страну при ремонте — передать `--country` явно, он всегда важнее сохранённого значения.
При списке из нескольких `agentId` с разной сохранённой страной флаг, если передан, применяется
ко всем агентам одинаково — для разных стран нужны отдельные запуски.

## Как выполнять

```
ssh -i ~/.ssh/vps_key root@<VPS_HOST> "cd ~/openclaw-plugins/telegram-user-tool && \
  ./node_modules/.bin/tsx src/scripts/ops/provision-mobile-proxy.ts \
  --agents <agentId1,agentId2,...> \
  [--country <country>] \
  --max-attempts <N>"
```

`--country` — опускать флаг, если у всех агентов из списка уже есть сохранённая страна в
`tg-account.json` (обычный случай при повторном ремонте). Передавать явно только если страны ещё
нет ни у одного агента списка, либо юзер прямо просит сменить страну — тогда флаг применяется ко
всем агентам списка одинаково. Скрипт обрабатывает агентов **строго последовательно** (design.md,
Non-Goals — параллельно сознательно не делаем: этот же VPS уже показывал деградацию под
несколькими одновременными MTProto-подключениями).

## Что делает скрипт (кратко)

Для каждого агента: страна берётся из явного флага, а если флаг не передан — из уже сохранённого
`proxy.countryCode` в `tg-account.json` этого агента; если ни того ни другого нет — агент
помечается как «прекращено». Если у агента уже настроен прокси (`proxy.host`/`proxy.username`) —
сначала проверяется он (кандидат №0), не трогается, если ещё работает. Дальше цикл: взять
следующего ещё не занятого другим агентом кандидата из инвентаря asocks для этой страны →
проверить подключение (сессия агента, 3 попытки × 20с) → работает → сохранить в
`tg-account.json` (`type/host/port/username/password/countryCode`), следующий агент; не
работает → взять следующего кандидата. При исчерпании пула страны агент явно помечается
отдельным статусом («свободных прокси не осталось»), не путается с «не найден за N попыток».
**`tg-account.json` изменяется только при подтверждённом успехе** — при полном исчерпании
попыток или пула конфиг агента остаётся нетронутым. Уже выданный в рамках этого прогона
кандидат не предложится следующему агенту того же списка, даже до записи на диск.

## После выполнения

Показать пользователю итоговый вывод скрипта как есть — по каждому `agentId`: либо адрес
рабочего прокси, либо причина неудачи («не найден за N попыток» / «свободных прокси не
осталось»). Отдельно в Saved Messages это не отправляется (разовый интерактивный запуск, не
плановая задача).
