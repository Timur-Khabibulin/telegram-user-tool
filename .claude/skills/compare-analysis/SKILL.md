# Compare Analysis — Выбор варианта из нескольких

## Цель

Выбрать один вариант из нескольких (сервис, API, библиотека, инструмент, вендор) так,
чтобы результат был:

- **полным** — широкий охват кандидатов, а не первые два попавшихся;
- **проверяемым** — данные из первоисточников, единые оси сравнения;
- **честным** — пробелы помечены «проверить», а не выдуманы.

Метод универсальный, не привязан к конкретной предметной области.

---

## Алгоритм

### Шаг 1 — Зафиксировать критерии выбора

Выписать требования, по которым оценивается выбор. Среди них выделить **решающий
критерий** — тот, что отсекает кандидатов быстрее всего, и проверять его первым.

> Предохранитель: критерии формулируются **до** поиска. Иначе они подгоняются под
> первого найденного кандидата.

### Шаг 2 — Широкая разведка кандидатов

Собрать ландшафт: кто вообще есть на рынке, а не первые попавшиеся.

> Предохранители:
> - запросы **короткие и на одну функцию** (не сваливать все критерии в один запрос);
> - искать **на языке целевого рынка** (выдача на другом языке бывает шире/иной);
> - идти **от общего к частному** — сначала охват, потом детали по кандидатам.

### Шаг 3 — Категоризация и отсев

Разложить кандидатов по корзинам (например: подходит / не из этой категории /
доступен иначе) с **явной причиной дисквалификации** каждого отсеянного.

> Предохранитель: проверять **каждую сущность отдельно**, не склеивать похожие по
> названию в одну (разные домены/бренды с близкими именами — часто разные продукты).

### Шаг 4 — Глубокий анализ выживших

Для каждого живого кандидата собрать данные **из первоисточников** (официальная
документация, спецификации, прайс), а не по памяти: возможности, параметры,
ограничения, цены, лимиты.

### Шаг 5 — Сравнительная таблица

Свести кандидатов в таблицу по **единым осям** (у всех одни и те же строки).
**Решающий критерий** из шага 1 — отдельной строкой, чтобы он читался сразу.

### Шаг 6 — Расчёт под реальный сценарий

Посчитать стоимость/усилие под **целевой объём задачи** (а не абстрактно), с явно
выписанными допущениями.

### Шаг 7 — Рекомендация и честные пробелы

Дать вывод, **привязанный к критериям** из шага 1. Всё непроверенное пометить
«проверить» — не выдумывать недостающие цифры и факты.

### Шаг 8 — Итерация по новым требованиям

При появлении нового требования — перепроверить выполнимость у кандидатов, обновить
таблицу и рекомендацию, а не дописывать сбоку.

---

## Сквозной принцип

**Первоисточник важнее памяти; непроверенное помечается явно.** Это правило действует
на каждом шаге, а не только в выводе.
