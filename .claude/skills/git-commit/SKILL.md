# Git Commit — Составление и создание коммита

## Цель

Проанализировать незакомиченные изменения и создать коммит с лаконичным, информативным сообщением на русском языке.

---

## Алгоритм

### Шаг 1 — Изучить изменения

Выполни `git diff --stat HEAD` и `git status --short`, чтобы увидеть список изменённых файлов.

При необходимости прочитай ключевые файлы, чтобы понять суть изменений. Не читай весь diff — достаточно заголовков функций и новых экспортов.

### Шаг 2 — Составить сообщение коммита

Структура сообщения:

```
<тип>: <общее описание фичи или изменений — одной строкой, понятно аналитику>

<слой 1>: <что добавлено/изменено>
<слой 2>: <что добавлено/изменено>
...
```

**Правила:**

- Первая строка — короткое общее описание на русском. Что было сделано с точки зрения продукта/функциональности, без технических деталей.
- Тело коммита — описание по слоям (тулы, скиллы, схема БД, конфиг и т.д.). Одна строка на слой.
- Типы: `feat` (новая функциональность), `fix` (исправление), `refactor` (рефакторинг без изменения поведения), `chore` (конфиг, зависимости, инфра).
- Не упоминать детали реализации (названия переменных, типы данных, внутреннюю логику).
- Не писать «добавлен файл X» — писать что этот файл делает.

**Примеры слоёв для этого проекта:**

- `Тулы:` — новые или изменённые OpenClaw-тулы
- `Скиллы:` — новые или изменённые SKILL.md
- `БД:` — новые таблицы или миграции
- `Конфиг:` — изменения openclaw.json, package.json и т.п.
- `Спеки:` — изменения в openspec/

### Шаг 3 — Показать сообщение пользователю

Выведи итоговое сообщение коммита и спроси нужно ли создать коммит.
Если да - перейди к шагу 4, если нет - заверши выполнение скилла.

### Шаг 4 — Создать коммит

После подтверждения выполни:

```bash
git add <конкретные файлы, не git add -A>
git commit -m "..."
```

Не добавляй `.DS_Store`, `.env`, и другие служебные файлы.
