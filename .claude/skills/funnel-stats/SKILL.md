Строит Excel-таблицу дневной воронки с диаграммами. Данные берутся с VPS,
таблица **каждый раз создаётся с нуля** и кладётся в папку `funnel-reports/`.

## Что в таблице

Лист `Данные`, суммы по всем агентам за день (`Σ`). Столбцы B–E — сырьё/притоки из
`daily_stats`, F–H — производные (считает генератор, не SQL). `post_views_abs` из
запроса в таблицу не выводится (нужен только прирост):

| Колонка | Поле `daily_stats` | Значение |
|---|---|---|
| A Дата | `date` | день UTC+5 |
| B Ответы в группах (Σ) | `SUM(group_replies)` | ответы агентов в группах |
| C Подписчики (Σ abs) | `SUM(public_subs_abs)` | подписчики личных каналов (абсолют) |
| D Прирост просмотров (Σ) | `SUM(post_views_delta)` | прирост просмотров за день |
| E Прирост заявок в приват (Σ) | `SUM(private_requests_delta)` | прирост заявок в приватный канал, нетто со знаком (только admin-агент) |
| F Притоки заявок (Σ) | `max(E, 0)` | положительная часть E: новые заявки без приёма в канал |
| G Конверсия просмотр/ответ | `D / B` | сколько просмотров даёт один ответ за день |
| H Конверсия СС-3 | скользящее среднее G за 3 дня | сглаживает дневной шум конверсии |

Первый день — базовый: его дельта = 0 как артефакт отсутствия предыдущего
снапшота, поэтому конверсия (G/H) для него пустая, и он исключён из анализа.

**5 диаграмм** правее данных (якорь автоматически правее последнего столбца, шаг 15
строк), сверху вниз: «Конверсия просмотр/ответ + тренд» (дневная конверсия G,
СС-3 H, линейная линия тренда с уравнением и R²) → 4 столбчатых: ответы (B),
подписчики (C), прирост просмотров (D), притоки заявок (F). У каждой диаграммы
подписаны **обе оси** (название + числовые деления); подписей значений на самих
столбцах/точках нет.

**Блок «Анализ за период»** — под таблицей на листе `Данные` (подпись в колонке A,
значение в C): корреляция Пирсона и линейная регрессия «прирост просмотров ~
ответы» одним числом за весь диапазон (коэффициенты `a`/`b`, уравнение, R²), период,
число дней, средняя конверсия. Это числовой ответ «насыщается ли воронка».

**Лист `Описание`** — по каждому производному параметру (притоки заявок, конверсия,
СС-3, корреляция Пирсона, R², регрессия `a`/`b`, средняя конверсия): что это, зачем
нужен (что определяет) и как вычисляется.

## Источник данных

`funnel.db` админ-агента (`agent1`) на VPS. Подключение — `ssh -i ~/.ssh/vps_key`,
хост `root@<VPS_HOST>` (см. skill `vps`). Метрики собирает таймер
`tg-funnel-tracker` (19:10 UTC) — за сегодняшний день строки может ещё не быть,
это нормально.

## Как выполнять

Один конвейер: запрос на VPS → генератор. `COALESCE(...,0)` приводит `NULL`-дельты
первого дня к `0` (как в исходной таблице). Отрицательная дельта заявок (например
−77) — норма, не обнулять.

```bash
mkdir -p funnel-reports
ssh -i ~/.ssh/vps_key root@<VPS_HOST> 'sqlite3 -separator "|" \
  ~/.openclaw/workspace-agent1/funnel.db \
  "SELECT date, SUM(group_replies), SUM(public_subs_abs), SUM(post_views_abs), \
          COALESCE(SUM(post_views_delta),0), COALESCE(SUM(private_requests_delta),0) \
   FROM daily_stats GROUP BY date ORDER BY date;"' \
| python .claude/skills/funnel-stats/build_funnel_xlsx.py \
    "funnel-reports/funnel-stats-$(date +%Y-%m-%d).xlsx"
```

Имя файла — с текущей датой, поэтому прошлые отчёты не затираются. SQL отдаёт те
же 6 полей, что и раньше; конверсию, статистику и описания генератор считает сам.
Генератор печатает строку-итог (число строк, диапазон дат, число диаграмм, листы) —
показать её пользователю и назвать путь к файлу.

## Важно про инструмент

- **Создание с нуля** (этот скил) → `openpyxl`: диаграммы строятся и якорятся
  корректно.
- **Дополнение готового xlsx с диаграммами** → НЕ через `openpyxl` (он не двигает
  диапазоны существующих графиков). Этот скил всегда строит заново, поэтому проблемы
  нет.

Генератор: `build_funnel_xlsx.py` (рядом с этим файлом). Читает результат запроса
со stdin (6 полей через `|`), считает производные столбцы и статистику, пишет xlsx
в путь из первого аргумента.
