## Why

Channel Discovery v1 отсекает каналы только по числу подписчиков. Это ненадёжный прокси качества: каналы с накрученной или мёртвой аудиторией проходят единственный гейт и засоряют список каналов агентов. Нужен второй гейт — по среднему охвату публикации — чтобы агенты вступали только в каналы с живой аудиторией.

## What Changes

- Добавляется опциональный параметр `min_avg_post_reach` в скилл `channel-discovery` и оркестратор discovery.
- Для кандидатов, прошедших гейт подписчиков, запрашивается средний охват публикации через TGStat `channels/stat`.
- Если TGStat не вернул данные — система вычисляет средний охват вручную по последним публикациям канала через Telegram. Если и это не дало результата — кандидат отсеивается (fail-closed).
- Аккаунт для ручного вычисления охвата задаётся оператором через скилл. Без указанного аккаунта ручное вычисление не производится и канал не проходит гейт.
- Кандидаты с охватом ниже порога отсеиваются до постановки в очередь вступления.
- Счётчик отсеянных по охвату добавляется в отчёт оператору.
- Если параметр не задан — поведение остаётся как в v1 (гейт не применяется).

## Capabilities

### New Capabilities

- `channel-discovery-avg-reach-gate`: гейт отбора каналов по среднему охвату публикации через TGStat; MTProto fallback при недоступности данных TGStat; fail-closed если ни один источник не дал данных; аккаунт для fallback задаётся оператором; опциональность параметра; учёт отсева в отчёте.

## Impact

- `src/core/discovery/tgstat.ts` — новая функция `getChannelStat`; обновление комментария-шапки.
- `src/core/discovery/run.ts` — `RunParams`: `minAvgPostReach`, `avgReachAgentId`, `telegramService`; счётчик `rejectedByAvgReach` в `RunResult`; логика MTProto fallback в цикле.
- `src/core/telegram/service.ts` — метод для получения просмотров последних постов канала по username.
- `skills/channel-discovery/SKILL.md` — новые необязательные параметры `min_avg_post_reach` и `avg_reach_agent` в шагах 1 и 3.
- Зависимости: TGStat API (метод `channels/stat`); Telegram MTProto (чтение истории канала).
- Без изменений: схема `discovered_channels`, `join_queue`, `monitor`, round-robin, дедуп.
