## Context

Ежедневный отчёт-воронка (`funnel-tracker.ts` → `collectFunnel` → `renderFunnel`/
`buildFunnelCsv`) уже собирает метрики 1-7 этапов воронки по каждому агенту и
шлёт текст + CSV в Saved Messages. `telegram-error-handling` добавил два новых
источника данных, которых отчёт ещё не читает:

- `channels.status`/`statusUpdatedAt` (per-agent `tg-channels.db`) — `banned`
  проставляется в `monitor-v2` при `chat_write_forbidden`/`user_banned_in_channel`.
- `agent_restrictions` (платформенная `agent-restrictions.db`, одна БД на всех
  агентов, лежит в workspace `FUNNEL_ADMIN_AGENT_ID`) — одна строка на `agentId`
  с `restriction_type`/`restricted_at`, обновляется диспетчером при account-fatal
  ошибках.

## Goals / Non-Goals

**Goals:**
- Показать в CSV число каналов, забаненных за отчётные сутки, по каждому агенту.
- Показать в CSV список агентов, получивших ограничение за отчётные сутки, с типом ограничения.
- Показать в тексте отчёта агрегированное число таких агентов.

**Non-Goals:**
- Не считать текущий снимок активных ограничений (`getActiveRestriction`) — только новые/повторные события за сутки.
- Не менять поведение самих ограничений/статусов каналов (`agent-restrictions.ts`, `monitor-v2.ts`) — только чтение для отчёта.
- Не добавлять список забаненных каналов (названия/id) в отчёт — только счётчик; это симметрично уже существующему `sendErrors` (число, без списка) в главной CSV-таблице.

## Decisions

**1. `channelsBannedToday` — окно то же, что у остальных метрик этапов 1-4.**
`countChannelsBannedInWindow(agentId, startSec, endSec)` — сигнатура и место
вызова зеркалят уже существующую `countVisitsToday`: тот же `window.startSec/endSec`,
тот же try/catch в блоке этапов 1-4 `collectFunnel` (сбой БД одного агента не
рушит прогон, значение остаётся 0). Не переиспользует `countRecentlyBannedChannels`
(другая семантика — скользящее окно от `now()` для триггера suspend, а не
окно отчётного дня).

**2. `restrictedAgents` — платформенный список, не per-agent.**
`agent_restrictions` — общая БД (не per-agent, как `funnel.db`/`discovery.db`).
`listRestrictionsSince(adminAgentId, startSec, endSec)` вызывается один раз вне
цикла по агентам, как уже сделано для `privateAbsByAgent` (заявки в приватный
канал через `REPORT_AGENT_ID`). Список НЕ фильтруется по `activeAgentIds`:
ограничение — платформенный факт, не связанный с тем, попал ли агент в текущую
выборку активных по задачам (`isAgentActive`).

**3. Фильтр «за отчётные сутки» = `restricted_at ∈ [window.startSec, window.endSec)`.**
`agent_restrictions` хранит одну строку на agentId (REPLACE при повторном
срабатывании), не журнал событий. `restricted_at` обновляется при каждой
простановке (первой и повторных), поэтому фильтр по окну корректно даёт «кому
наложено сегодня», не «кто сейчас под ограничением» — иначе `need_update_session`
(не снимается автоматически) попадал бы в отчёт на каждый последующий день.
Обратная сторона: если ограничение наложено и снято (`clearRestriction`) в
пределах одних суток до прогона отчёта, оно не попадёт в отчёт (строка удалена).
Это принято как приемлемое: снятое в тот же день ограничение не требует
внимания оператора post-factum.

**4. Третья таблица в CSV, а не столбцы в главной.**
`restriction_type` — категориальное значение, не число, не сворачивается в
столбец главной таблицы (та строится из чисел агента). Использован уже
существующий в файле паттерн второй таблицы (`channelBreakdown` — построчная
разбивка по каналам после пустой строки) — добавляется третья таблица тем же
способом.

**5. В тексте — только число, без списка.**
Текстовое сообщение уже ограничено шириной мобильного экрана (см. комментарий
в начале `funnel-report.ts`); детали (agentId, restriction_type) — только в CSV,
как и разбивка по каналам (US-5) уже сделана только для CSV.

## Risks / Trade-offs

- [Расхождение между «наложено сегодня» и «активно сейчас»] → задокументировано
  в proposal.md и здесь; при необходимости снимка текущего состояния это будет
  отдельное расширение (`getActiveRestriction` по всем агентам), не входит в этот change.
- [`agent_restrictions` пуста/не существует] → `listRestrictionsSince` возвращает
  пустой список (таблица создаётся идемпотентно при открытии, как в `agent-restrictions.ts`), отчёт не падает.
