## Why

Сейчас `tg-agent-autoregistration` в рамках `prepareAccount` **всегда** создаёт
публичный канал персоны (шаг 6, `createPersonaChannel`). Нужно разделить два
сценария: (а) быстрая рега пачки агентов без канала и (б) создание публичных
каналов отдельным прогоном позже — на той же (или части) пачке уже
зарегистрированных агентов. Это даёт гибкость: сначала завести аккаунты, затем
контролируемо создавать каналы, затем — приватные ссылки существующим скиллом
`private-invite-links`.

## What Changes

- **Флаг создания канала в реге.** Новый параметр `createPublicChannel` у
  `tg_agent_autoregistration_run`. Шаг `createPersonaChannel` в `prepareAccount`
  становится условным:
  - `false` — mode A: агент с профилем/фото/username, БЕЗ публичного канала;
  - `true` — mode B: как сейчас (рега + публичный канал; приватная ссылка —
    по-прежнему отдельным шагом, не инлайн).
- **Новый отдельный batch-скилл создания канала** (`tg_agent_channel_setup`):
  для списка уже зарегистрированных агентов подключается **через сессию агента**
  (не bootstrap tdata), читает персону из `tg-account.json`, создаёт публичный
  канал и закрепляет его в профиле (переиспользует уже вынесенный
  `createPersonaChannel`). Guard: агенты, у которых personal/pinned-канал уже
  установлен, **пропускаются** (защита от дублей и `CHANNELS_ADMIN_PUBLIC_TOO_MUCH`).
- **Приватные ссылки не трогаем** — остаются существующим `private-invite-links`,
  запускаемым третьим шагом после создания каналов.

## Impact

- Спека `tg-agent-autoregistration`: требование «Account setup» — создание канала
  условно (флаг).
- Новая способность `persona-channel-setup`: batch-создание канала для готового
  агента.
- Код: `run.ts`/`account-setup.ts` (условный шаг), `index.ts` (новый параметр +
  новый тул), новый скилл `skills/tg-agent-channel-setup/SKILL.md`, обёртка над
  `createPersonaChannel` с подключением через `TelegramService` по сессии агента.
- Персона выбирается на шаге 1 (реге), персистится в `tg-account.json.persona`,
  новый скилл её оттуда читает — переуказывать не нужно.

## Порядок архивации

Этот change следует архивировать **после** `tg-autoreg-gdrive-2fa-input`
(уже задеплоен, но не заархивирован): оба меняют требование «Account setup on the
bootstrap session», и дельта здесь построена поверх его версии (2FA — из
`twoFaPassword` оператора).
