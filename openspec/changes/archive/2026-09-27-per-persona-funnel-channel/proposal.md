## Why

ID приватного канала воронки сейчас — одна захардкоженная константа
`FUNNEL_PRIVATE_CHANNEL_ID` (`src/core/config.ts`), общая на всю платформу: все
агенты всех персон льют заявки в один канал. При работе нескольких персон у каждой
должен быть свой приватный канал воронки, иначе заявки разных персон смешиваются и
их нельзя разнести по источнику.

## What Changes

- Приватный канал воронки задаётся **per-persona** — новое поле
  `funnelPrivateChannelId` в шаблоне персоны `profile_data.json`
  (`~/.openclaw/personas/<persona>/`), а не константой.
- **Модель A (admin остаётся единым):** `REPORT_AGENT_ID` (agent27) по-прежнему
  единственный админ всех персональных каналов и единственная сессия, создающая
  инвайт-ссылки и читающая заявки. Меняется только целевой `channelId` — резолвится
  по персоне агента.
- Создание инвайт-ссылок (деплой персоны и пачечный tg_private_invite_links) берёт
  канал из шаблона персоны агента вместо константы.
- Сбор воронки читает канал персоны для каждого агента; если у персоны нет поля
  `funnelPrivateChannelId` — **подсчёт заявок по этой персоне пропускается** с
  пометкой (остальные метрики агента собираются как прежде).
- Итог заявок в отчёте воронки — **по персонам** (было: единый платформенный итог).
- **BREAKING (данные):** после выката существующий канал `-1003698044714` нужно
  вписать в `profile_data.json` персоны maria, иначе её заявки перестанут считаться.
  Правка данных на сервере, не кода.
- Константа `FUNNEL_PRIVATE_CHANNEL_ID` и аргумент `--private-channel` скрипта
  funnel-tracker удаляются (источник истины — шаблон персоны).

### Modified Capabilities
- `persona-template`: `profile_data.json` получает опциональное поле
  `funnelPrivateChannelId` (id приватного канала воронки персоны).
- `private-invite-links`: инвайт-ссылка создаётся в приватный канал **персоны
  агента**, а не в общий константный; при отсутствии канала у персоны ссылка не
  создаётся.
- `funnel-metrics`: заявки считаются по каналу персоны агента; персона без канала
  пропускается по этапу заявок; итог агрегируется по персонам.
- `funnel-report`: итог заявок отображается по персонам, а не единым числом.
