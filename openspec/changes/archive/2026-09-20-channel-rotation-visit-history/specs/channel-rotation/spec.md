## REMOVED Requirements

### Requirement: Распределение по нагрузке (round-robin)

**Reason**: Правило выбора целевого агента переведено с нагрузки на историю
посещений — см. ADDED «Распределение по истории посещений (visit-count)».
Обоснование: `docs/design/channel-rotation/requirements-v2.md`.

**Migration**: Нагрузка агента (число активных каналов) больше не участвует в выборе.
Целевой агент определяется минимальным visit-count (число прошлых `assigned` по
каналу) с исключением источника; сортировка целей по нагрузке и курсор round-robin
удаляются.

## ADDED Requirements

### Requirement: Распределение по истории посещений (visit-count)

Система SHALL НЕ учитывать нагрузку агента (число активных каналов) при выборе
целевого агента. Для каждого кандидата система SHALL вычислять `visit-count` каждого
активного агента-цели персоны — число прошлых событий `assigned` по этому каналу для
этого агента-получателя в разрезе персоны (из журнала операций; агент без событий =
visit-count 0). Канал SHALL назначаться активному агенту с минимальным visit-count,
исключая агента-источник; при нескольких агентах с минимальным visit-count выбор
SHALL быть случайным. «Круги» SHALL возникать как следствие правила минимума: пока
есть агенты с visit-count 0 — канал достаётся им; когда у всех подходящих
visit-count ≥ 1, минимум становится 1, и так далее. Выбор для каждого кандидата
независим — общего курсора обхода целей нет.

#### Scenario: Канал уходит агенту, у которого его ещё не было

- **WHEN** в прогоне есть кандидат и среди активных агентов-целей (кроме источника)
  есть агенты с visit-count 0
- **THEN** канал назначается одному из агентов с visit-count 0 (у которого канала ещё
  не было), независимо от их нагрузки

#### Scenario: Случайный выбор среди равных по минимуму

- **WHEN** минимальный visit-count имеют несколько активных агентов-целей
- **THEN** целевым может оказаться любой из них — выбор между ними случайный

#### Scenario: Повтор только после полного круга

- **WHEN** канал уже побывал у всех активных агентов персоны по одному разу
  (у всех visit-count ≥ 1)
- **THEN** канал достаётся агенту с наименьшим visit-count (новый круг), а не
  произвольному ранее пробовавшему

#### Scenario: Нет подходящей цели

- **WHEN** единственный активный агент персоны — источник этого канала
- **THEN** канал остаётся нераспределённым (`unassigned`)

## MODIFIED Requirements

### Requirement: Перенос назначения

Для каждого кандидата, которому подобран целевой агент, SHALL выполниться:
регистрация канонической ссылки (`normalizeChannelLink(channelUsername)`) за
новым агентом в реестре `discovered_channels` (переиспользуя существующий
`forceAssignChannel`), постановка этой ссылки в `join_queue` целевого агента
(`addJoinQueue`), и удаление строки канала из таблицы `channels` агента, где
канал был забанен. Целевым агентом для канала SHALL не может быть выбран тот
же агент, у которого этот канал был забанен — агент-источник исключается из
числа кандидатов на выбор.

#### Scenario: Успешный перенос канала

- **WHEN** кандидат `chatId` у агента A назначен агенту B
- **THEN** `discovered_channels.assigned_agent` для этого канала становится
  B, ссылка канала появляется в `join_queue` агента B, а строка `chatId` в
  `channels` агента A удаляется

#### Scenario: Исходный агент не назначается сам себе

- **WHEN** агент A является источником этого канала (канал был у A забанен)
- **THEN** A исключается из кандидатов, и канал получает другого активного агента
  персоны, а не A
