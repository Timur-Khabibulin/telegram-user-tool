## ADDED Requirements

### Requirement: CSV-вход с колонкой ссылок
Скрипт `channel-metrics.ts` SHALL принимать путь к входному CSV-файлу через параметр `--input`, читать из него значения колонки `link`, и игнорировать все прочие колонки входного файла.

#### Scenario: Входной CSV содержит дополнительные колонки
- **WHEN** входной CSV содержит колонки `link,title,agentId` в любом порядке
- **THEN** скрипт обрабатывает только значения колонки `link`, значения прочих колонок не используются и не переносятся в вывод

#### Scenario: Входной CSV не содержит колонку link
- **WHEN** во входном CSV отсутствует колонка `link`
- **THEN** скрипт завершается с ошибкой и не создаёт/не изменяет выходной файл

### Requirement: Расчёт метрик канала через MTProto
Для каждой ссылки, которую удалось резолвить в канал, скрипт SHALL получить через MTProto (сессия агента, заданного параметром `--agent`): число подписчиков, средний охват последних постов, признак наличия привязанной группы обсуждения (комментарии открыты) и признак типа канала (broadcast или нет).

#### Scenario: Публичный broadcast-канал с открытыми комментариями
- **WHEN** ссылка резолвится в публичный broadcast-канал с привязанной группой обсуждения и историей из 11+ постов
- **THEN** выходная строка содержит `subs_count` (число), `avg_views` (число), `comments_open=true`, `is_broadcast=true`, `error` пусто

#### Scenario: Канал без привязанной группы обсуждения
- **WHEN** ссылка резолвится в broadcast-канал без привязанной группы обсуждения
- **THEN** выходная строка содержит `comments_open=false`, остальные метрики заполнены как обычно

#### Scenario: Средний охват — методология coverage-update
- **WHEN** скрипт вычисляет `avg_views` для канала с 11 и более постами
- **THEN** значение — среднее по просмотрам постов с индекса 1 по 10 включительно (самый свежий пост, индекс 0, исключается из расчёта)

#### Scenario: Канала с менее чем 2 постами
- **WHEN** у резолвленного канала меньше 2 постов в истории
- **THEN** `avg_views` в выходной строке пусто (не вычисляется), остальные метрики (подписчики, комментарии, тип) заполняются как обычно

### Requirement: Обработка нерезолвящихся и приватных ссылок
Скрипт SHALL записывать строку в выход для каждой входной ссылки независимо от того, удалось ли её резолвить; если резолв невозможен (приватная ссылка без username, канал не найден, недоступен), метрики в строке SHALL быть пустыми, а причина SHALL быть записана в колонку `error`.

#### Scenario: Приватная ссылка без username
- **WHEN** входная ссылка имеет вид `t.me/+...` или `t.me/joinchat/...`
- **THEN** скрипт не выполняет MTProto-резолв для этой ссылки, выходная строка содержит пустые `subs_count,avg_views,comments_open,is_broadcast` и непустой `error`

#### Scenario: Публичная ссылка на несуществующий или недоступный канал
- **WHEN** `resolveChannelByUsername` не находит канал по ссылке
- **THEN** выходная строка содержит пустые метрики и непустой `error`, прогон продолжается со следующей ссылкой

### Requirement: Построчная (инкрементальная) запись результата
Скрипт SHALL дописывать каждую обработанную строку в выходной CSV сразу после обработки соответствующего канала, не накапливая результат в памяти до завершения всего прогона.

#### Scenario: Прогон прерван на середине списка
- **WHEN** прогон обработал 150 из 300 входных ссылок и был прерван (ошибка, остановка процесса)
- **THEN** выходной файл содержит результаты по всем 150 обработанным до прерывания ссылкам

### Requirement: Резюмируемость повторного запуска
При повторном запуске с тем же значением `--output`, указывающим на существующий файл, скрипт SHALL пропускать входные ссылки, чья нормализованная форма (см. `normalizeChannelLink`) уже присутствует в колонке `link` выходного файла, независимо от того, содержит ли соответствующая строка метрики или `error`, и SHALL обрабатывать только оставшиеся ссылки.

#### Scenario: Повторный запуск после обрыва
- **WHEN** выходной файл уже содержит результаты (успешные и с `error`) по 150 из 300 ссылок, скрипт запускается повторно с тем же `--input` и `--output`
- **THEN** скрипт не выполняет MTProto-запросы для уже присутствующих в выходном файле 150 ссылок и обрабатывает оставшиеся 150

#### Scenario: Одна и та же ссылка в разных нормализованных формах
- **WHEN** выходной файл содержит строку с `link=https://t.me/foo`, а входной CSV содержит ту же ссылку в виде `@foo` или `http://t.me/foo/`
- **THEN** скрипт распознаёт её как уже обработанную (по нормализованной форме) и пропускает

### Requirement: Единая сессия одного агента на прогон
Скрипт SHALL требовать обязательный параметр `--agent <agentId>`, использовать для всех MTProto-запросов прогона сессию только этого агента, и SHALL не переключаться на другие сессии в рамках одного запуска.

#### Scenario: Параметр --agent не указан
- **WHEN** скрипт запущен без параметра `--agent`
- **THEN** скрипт завершается с ошибкой до выполнения каких-либо MTProto-запросов

### Requirement: Защита от FLOOD_WAIT
Скрипт SHALL выдерживать паузу между последовательными MTProto-вызовами и SHALL останавливать весь прогон, если подряд получено два ответа `FLOOD_WAIT`, не пытаясь продолжить обработку оставшихся ссылок в этом запуске.

#### Scenario: Два FLOOD_WAIT подряд
- **WHEN** два последовательных MTProto-вызова в рамках прогона возвращают `FLOOD_WAIT`
- **THEN** скрипт останавливает обработку оставшихся ссылок; уже записанные в `--output` строки остаются на диске для последующего резюмируемого перезапуска
