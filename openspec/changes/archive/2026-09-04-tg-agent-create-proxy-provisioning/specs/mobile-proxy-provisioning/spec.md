## MODIFIED Requirements

### Requirement: Автоматический подбор рабочего мобильного прокси для списка агентов

Система SHALL по заданному списку `agentId` автоматически подбирать рабочий мобильный прокси
через API asocks.com: для каждого агента последовательно создавать кандидата (страна/регион/
город — из явно переданных входных параметров, либо, если не переданы, из значений, сохранённых
в `tg-account.json` этого агента с предыдущего успешного подбора), проверять его реальным
MTProto-подключением с сессией этого же агента, и при неудаче удалять кандидата и создавать
следующего — до конфигурируемого предела попыток (`--max-attempts`, по умолчанию 5).

#### Scenario: Рабочий прокси найден с первой попытки

- **WHEN** первый созданный кандидат успешно проходит проверку подключения
- **THEN** его данные сохраняются в `tg-account.json` агента, попытки прекращаются, дальнейшие
  кандидаты не создаются

#### Scenario: Несколько кандидатов подряд не работают

- **WHEN** кандидат не проходит проверку подключения
- **THEN** он удаляется на стороне asocks, создаётся следующий кандидат, попытки продолжаются до
  успеха или до исчерпания `--max-attempts`

#### Scenario: Предел попыток исчерпан

- **WHEN** ни один из `--max-attempts` кандидатов не прошёл проверку
- **THEN** `tg-account.json` агента остаётся без изменений, в итоговом отчёте по этому агенту
  явно указано, что рабочий прокси не найден за N попыток

#### Scenario: Страна/регион/город не переданы явно

- **WHEN** запуск не содержит флагов `--country`/`--state`/`--city`, а `tg-account.json` агента
  уже содержит сохранённые `countryCode/state/city` с предыдущего успешного подбора
- **THEN** система использует эти сохранённые значения для создания кандидатов, не запрашивая
  регион у юзера повторно

#### Scenario: Ни явных параметров, ни сохранённых значений нет

- **WHEN** флаги `--country`/`--state`/`--city` не переданы, и `tg-account.json` агента не
  содержит сохранённой локации (агент создан до появления этого механизма)
- **THEN** система требует явно передать `--country` (регион/город — по прежним правилам,
  опционально), не может подобрать прокси без хотя бы страны

### Requirement: Конфигурация агента изменяется только при подтверждённом успехе

Проверка кандидата прокси SHALL происходить без записи на диск — `tg-account.json` агента
изменяется ровно один раз, при первом успешно прошедшем проверку кандидате, и ни разу иначе
(в т.ч. при полном исчерпании попыток или падении скрипта посреди цикла). Сохраняемые при успехе
поля прокси SHALL включать `countryCode/state/city`, использованные для этого кандидата, — не
только `type/host/port/username/password/name`.

#### Scenario: Падение скрипта посреди цикла не портит конфиг

- **WHEN** скрипт прерывается (ошибка, ручная остановка) после создания и неудачной проверки
  нескольких кандидатов, но до нахождения рабочего
- **THEN** `tg-account.json` агента остаётся точно таким же, каким был до запуска скрипта

#### Scenario: Успешный подбор сохраняет локацию вместе с остальными полями прокси

- **WHEN** кандидат прокси успешно проходит проверку
- **THEN** в `tg-account.json` записываются вместе: `type/host/port/username/password/name` и
  `countryCode/state/city`, использованные при создании этого кандидата
