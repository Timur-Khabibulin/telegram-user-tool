## Why

Создание нового Telegram-агента (`skills/tg-agent-create/SKILL.md`) сегодня — пошаговый
markdown-сценарий, который LLM выполняет ~10 отдельными bash-вызовами и куда юзер вручную
вставляет полный текст `SOUL.md` и данные ручного socks5-прокси. Это дорого по токенам (текст
персоны проходит через контекст модели туда и обратно, хотя все ~45 агентов уже используют одну
и ту же персону) и требует от человека заранее вручную создавать прокси на asocks — ручной труд,
который `mobile-proxy-provisioning` (эта же платформа, отдельный change) уже автоматизировала для
**ремонта** сломанных прокси, явно оставив интеграцию в создание агента как следующий шаг
(Non-Goals того change). Это тот следующий шаг.

## What Changes

- `skills/tg-agent-create/SKILL.md` переписывается: убирается ручной ввод `proxy.host/port/
  username/password` и запрос полного текста `SOUL.md` у юзера; данные аккаунта, полученные из
  Шага 3 (сейчас ~10 последовательных bash-вызовов), собираются одним новым скриптом.
- Прокси для нового агента подбирается автоматически (asocks) до получения `sessionString` —
  цикл создание-кандидата → проверка → удаление-при-неудаче, до `--max-attempts` (по умолчанию 5),
  аналогично уже существующему репейр-циклу `mobile-proxy-provisioning`, но с проверкой без
  сессии (её ещё нет).
- Проверка кандидата — новый метод `TelegramService`: только MTProto `connect()`/`disconnect()`,
  без `Api.auth.SendCode`. Существующий `authSendCode` шлёт реальный код при каждом вызове —
  использовать его для перебора кандидатов означало бы слать код на каждую неудачную попытку и
  упереться в флуд-лимит Telegram до входа в аккаунт.
- Выбор страны/региона/города прокси — два режима на выбор юзера: ввод готовых значений текстом,
  либо пошаговый подбор через списки `asocks` (`/dir/countries` → `/dir/states` → `/dir/cities`),
  чтобы избежать опечаток (API требует точных совпадений имён state/city).
- `ProxyConfig` (`src/core/config.ts`) получает новые опциональные поля `countryCode`, `state`,
  `city` — персистятся в `tg-account.json` при первом успешном подборе, чтобы повторный ремонт
  прокси (`mobile-proxy-provision`) не запрашивал регион у юзера заново.
- `SOUL.md` нового агента — прямая копия эталонного файла из `~/.openclaw/workspace-agent1/
  SOUL.md` (одна персона на всех агентов), без передачи текста через юзера/модель.

## Capabilities

### New Capabilities

- `tg-agent-create`: полный процесс создания нового Telegram-агента — сбор минимальных входных
  данных, автоматический подбор мобильного прокси до входа в аккаунт, авторизация сессии,
  скриптовое создание файловой структуры/биндинга, копирование эталонной персоны, верификация
  установки. Формализует поведение, которое сегодня существует только как markdown-скилл без
  нормативной спеки.

### Modified Capabilities

- `mobile-proxy-provisioning`: конфигурация прокси (`tg-account.json`) дополнительно хранит
  `countryCode/state/city`; репейр-цикл использует эти сохранённые значения по умолчанию,
  запрашивая регион у юзера только если поля отсутствуют (агенты, созданные до этого change) или
  юзер явно хочет его сменить. `--country/--state/--city` становятся необязательным override, а
  не обязательными параметрами.

  Примечание: capability `mobile-proxy-provisioning` реализована (change `mobile-proxy-
  provisioning` — все задачи выполнены), но ещё не заархивирована в `openspec/specs/` — delta-
  спека этого change пишется против неё как против фактического текущего поведения.

## Impact

- Код: `src/core/config.ts`, `src/core/proxy/asocks-client.ts` (новые `listCountries/listStates/
  listCities`), `src/core/telegram/service.ts` (новый probe-метод), `src/scripts/provision-
  mobile-proxy.ts` (persist + optional override), новый скрипт создания агента (create-флоу,
  верификация без сессии — отдельный от `provision-mobile-proxy.ts`), новый скрипт-скаффолд для
  файловой структуры агента (по образцу `skills/tg-agent-create/scripts/verify-agent.sh`).
- Skills: `skills/tg-agent-create/SKILL.md` (переписывается), `.claude/skills/mobile-proxy-
  provision/SKILL.md` (country/state/city — опциональны).
- Данные: `ProxyConfig.countryCode/state/city` — новые опциональные поля, обратная совместимость
  сохраняется (существующие `tg-account.json` без них продолжают работать, репейр просто
  запрашивает регион как раньше).
- Вне скоупа: архивация change `mobile-proxy-provisioning` (отдельное административное действие,
  не блокирует эту работу); ротация/очистка уже существующих прокси без сохранённого региона.
