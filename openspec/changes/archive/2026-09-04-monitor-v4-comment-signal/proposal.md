## Why

`monitor-v4` (ветка «Открыт», §2b.iv) сейчас отбирает пост дня и решает,
комментировать ли его, глядя только на текст самого поста — многие посты
канала слабо информативны сами по себе (короткая подпись к медиа, заголовок),
но собирают живое обсуждение в комментариях. Нужно, чтобы кандидатом на
комментарий был не «пост», а «пост + обсуждение под ним»: отсеивать посты без
достаточного отклика (< 3 комментариев) ещё до LLM, а решение писать/не писать
и сам текст комментария строить на основе доминирующего мнения аудитории в
комментариях, а не только текста поста.

## What Changes

- §2b.iv `monitor-v4` (`src/skills/monitor-v4.ts`): числовой гейт по тексту
  поста (`passesPrefilter`) заменяется гейтом по числу комментариев — если у
  найденного поста дня меньше 3 комментариев, пост отбрасывается без
  обращения к LLM (тот же приём, что текущий `passesPrefilter`, но критерий и
  источник данных другие).
- Комментарии к посту становятся обязательным входом LLM-решения — новый
  метод `TelegramService` для получения комментариев поста канала
  (`messages.GetReplies`) с пагинацией до исчерпания всех комментариев
  (общее число — `.count` того же ответа, используется для гейта).
- Новая функция промпта `generatePostCommentV4` (`src/llm/prompts.ts`,
  текст согласован отдельно) и новая zod-схема ответа: `{ оценка: 0-4,
  решение: "пропустить" | "комментировать", главное_мнение: string | null,
  комментарий: string | null }` — заменяет вызов `generatePostCommentV3` в
  `monitor-v4.ts` (`monitor-v3.ts` не меняется, `generatePostCommentV3`
  остаётся его источником истины).
- Порядок шагов §2b `monitor-v4` меняется: обращение к обсуждению поста
  (сейчас — только после решения LLM, для поиска места ответа) переносится
  до LLM-вызова, так как комментарии теперь часть входа решения, а не только
  цели отправки.
- Отдельный контент-фильтр отдельных комментариев не вводится — очистка от
  шума (флуд, оффтоп, боты, конфликты между комментаторами) — часть самого
  промпта `generatePostCommentV4`, не код.

## Capabilities

### New Capabilities
(нет)

### Modified Capabilities
- `channel-post-watch-v4`: добавляется требование к отбору кандидата на
  комментарий — обязательное минимальное число комментариев поста (гейт до
  LLM) и обязательное использование содержимого комментариев (не только
  текста поста) при решении, комментировать ли пост и что написать.

  Примечание: `channel-post-watch-v4`, как и `channel-post-watch` до неё, ещё
  не влилась в `openspec/specs/` — её единственное определение сейчас лежит в
  незаархивированном change `monitor-v4`
  (`openspec/changes/monitor-v4/specs/channel-post-watch-v4/spec.md`). Этот
  change добавляет к ней ещё один блок требований по той же капабилити — оба
  должны влиться в `openspec/specs/channel-post-watch-v4/spec.md` при
  архивации (сначала `monitor-v4`, затем этот change, либо одновременно).

## Impact

- `src/core/telegram/service.ts` — новый метод получения комментариев поста
  канала (`messages.GetReplies`, пагинация, резолв `fromName` авторов).
- `src/llm/prompts.ts` — новая функция `generatePostCommentV4` рядом с
  `generatePostCommentV3` (не изменяется).
- `src/skills/monitor-v4.ts` — §2b.iv-v переписаны: гейт по числу
  комментариев вместо `passesPrefilter(post.text)`, обращение к обсуждению
  поднято до LLM-вызова, новая схема ответа и ветвление по `решение`.
- Наблюдаемое поведение: у агентов на `monitor-v4` меняется, на какие посты
  дня приходит реакция (только посты с ≥3 комментариями) и на основании чего
  строится сам комментарий (мнение аудитории, не пересказ поста).
- Нагрузка: на каждый найденный пост дня (а не только на те, что прошли
  отбор LLM) добавляется MTProto-запрос(ы) за комментариями — с пагинацией на
  постах с большим числом комментариев.
