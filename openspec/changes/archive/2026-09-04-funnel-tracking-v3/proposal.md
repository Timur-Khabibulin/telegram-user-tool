## Why

Действующий отчёт воронки (funnel-tracking v2) собрал шум и слепые зоны за время эксплуатации: показатель интенсивности сообщений/час в «активных каналах» не используется для оценки конверсии, «сообщений отправлено» смешивает группы и личные сообщения в одном числе, отчёт не отличает активных агентов от де-факто отключённых, не показывает вклад отдельного агента в приток заявок в приватный канал и не даёт разбивки по конкретным каналам. Требования на устранение этого зафиксированы и утверждены в `docs/design/funnel-tracking/requirements-v3.md`, техническое решение — в `docs/design/funnel-tracking/architecture-v3.md`.

## What Changes

- Убрать показатель интенсивности сообщений/час из «каналов с активностью» — и в тексте отчёта, и в CSV.
- Заменить показатель «сообщений отправлено» на «каналы с отправкой» (число каналов с ≥1 сообщением за день, без учёта повторов). Личные сообщения (DM) полностью исключаются из отчёта воронки — без замены и без компенсирующего показателя (только в этом отчёте; `dm_history` и рассылка DM не затрагиваются).
- Добавить разбивку заявок в приватный канал по агенту — отдельный столбец и в тексте, и в CSV, формат «дельта (абсолют)», прочерк у агентов без настроенной пригласительной ссылки. Платформенный итог заявок вычисляется как сумма по агентам вместо отдельного независимого запроса.
- Ограничить отчёт активными агентами: включаются только агенты с enabled задачей мониторинга (`monitor` или `monitor-v2`) на момент формирования отчёта; неактивные агенты не отображаются нигде — ни в тексте, ни в CSV, ни отдельной пометкой.
- Добавить в CSV вторую построчную таблицу — ежедневная разбивка «агент — канал (со ссылкой) — число сообщений за день».
- Все показатели «за отчётный день», включая новую разбивку по каналам, считаются строго в границах суток UTC+5 — действующая конвенция отчёта, без исключений.

## Capabilities

### New Capabilities
(нет — изменение целиком укладывается в существующие способности)

### Modified Capabilities
- `funnel-metrics`: убрать вычисление медианы интенсивности активности; переход с подсчёта числа сообщений на подсчёт числа каналов с отправкой (через разбивку по каналам, источник и для показателя, и для CSV-детализации); сбор заявок в приватный канал становится per-agent через персональные пригласительные ссылки (`private_invite_links`), платформенный итог — сумма по агентам; добавляется фильтр активных агентов (enabled `monitor`/`monitor-v2`) в начале сбора; DM полностью исключаются из сбора метрик воронки.
- `funnel-report`: рендер текста и CSV — убрать медиану из ячейки «Актив»; переименовать показатель «Отправлено» в «каналы с отправкой»; добавить столбец заявок по агенту в текст и CSV; добавить вторую таблицу в CSV с разбивкой по каналам и ссылкой на канал; отчёт перестаёт показывать агентов без активного мониторинга.

## Impact

- Код: `src/core/db/channels.ts`, `src/core/db/replies.ts`, `src/core/db/tasks.ts`, `src/core/telegram/service.ts`, `src/core/funnel-collect.ts`, `src/core/funnel-report.ts`. `src/core/db/funnel.ts` — без изменения схемы, используется полнее (существующие per-agent колонки `channel_snapshots`/`daily_stats` заполняются для всех агентов, не только `agent1`).
- Данные: новых таблиц/БД не заводится — переиспользуется `private_invite_links` (`private-invites.db`, изменение `private-invite-links`).
- Внешние потребители: скилл `funnel-stats` (Excel-отчёт на VPS) продолжает читать `daily_stats.group_replies`/`private_requests_delta` по прежнему контракту — `group_replies` не переименовывается и не меняет смысл в БД, только перестаёт отображаться в самом отчёте воронки; `private_requests_delta` начинает включать все агенты (раньше — только `agent1`), что для существующей формулы конверсии в `funnel-stats` даёт корректный платформенный итог без изменений в самом скилле.
- Зависимость: предполагает наличие персональных пригласительных ссылок в `private_invite_links` (изменение `private-invite-links`). Без них столбец заявок по агенту показывает прочерк у всех агентов — штатное поведение, не блокер запуска этого изменения.
