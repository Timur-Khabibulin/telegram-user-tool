## MODIFIED Requirements

### Requirement: Рендер ежедневного отчёта-воронки

Система SHALL формировать текстовый отчёт за завершившийся день UTC+5 с заголовком-датой и таблицей по активным агентам (агенты без включённой задачи мониторинга в таблицу не включаются) со столбцами: каналов у агента, каналов просмотрено, каналов с активностью (без интенсивности сообщений/час), каналов с отправкой (хотя бы одно сообщение группы за день; личные сообщения не учитываются), заявки в приватный канал по агенту, потенциальный охват. Столбец заявок SHALL выводиться в формате «дельта (абсолют)» (например `+13 (847)`), с прочерком у агента без настроенной пригласительной ссылки. Отчёт SHALL содержать строку **Итого** с суммами по всем столбцам, включая сумму заявок по агентам как платформенный итог.

#### Scenario: Полный отчёт за день

- **WHEN** собраны метрики по всем активным агентам
- **THEN** отчёт содержит дату дня UTC+5, строку на каждого активного агента и строку «Итого» с суммами, включая платформенный итог заявок

#### Scenario: Столбец заявок в формате дельта-абсолют

- **WHEN** рендерится столбец заявок в приватный канал агента
- **THEN** значение имеет формат `<дельта> (<абсолют>)`, либо `—`, если у агента не настроена пригласительная ссылка

#### Scenario: Неактивный агент не отображается

- **WHEN** у агента отключены обе версии задачи мониторинга
- **THEN** агент отсутствует в таблице отчёта и не участвует в строке «Итого»

### Requirement: Пометки о пропущенных данных

Отчёт SHALL явно отмечать агентов и метрики, пропущенные из-за ошибок или отсутствия данных (нет personal channel, недоступны заявки, агент недоступен), чтобы пробелы были видимы, а не молчаливы.

#### Scenario: Агент пропущен

- **WHEN** агент пропущен при сборе метрик (сбой этапов сбора, не фильтр активности)
- **THEN** в отчёте он помечен как пропущенный с краткой причиной

#### Scenario: У агента нет пригласительной ссылки

- **WHEN** у активного агента нет записи в `private_invite_links`
- **THEN** его ячейка заявок в таблице отчёта — прочерк («—»), отдельная пометка под таблицей не требуется

#### Scenario: Весь сбор заявок недоступен

- **WHEN** сбор заявок по всем агентам целиком не удался (нет прав у администратора приватного канала, ошибка запроса)
- **THEN** под таблицей выводится отдельная строка «Заявки в приватный канал: недоступно (…)», объясняющая, почему у всех агентов в столбце заявок «—»

## ADDED Requirements

### Requirement: CSV-вложение отчёта-воронки

Система SHALL формировать CSV-вложение с двумя таблицами: основной построчной таблицей по активным агентам (полная детализация метрик, включая заявки по агенту, без столбца интенсивности сообщений/час) и, отдельно после пустой строки, построчной разбивкой «агент — канал — ссылка на канал — число сообщений за отчётный день» только по каналам, куда агент реально отправлял сообщения в этот день.

#### Scenario: Основная таблица без медианы

- **WHEN** формируется CSV-вложение
- **THEN** в основной таблице отсутствует столбец интенсивности сообщений/час; столбец «сообщений отправлено» заменён на «каналов с отправкой»

#### Scenario: Разбивка по каналам

- **WHEN** агент отправил за отчётный день сообщения в несколько каналов
- **THEN** для каждого такого канала — отдельная строка во второй таблице CSV с числом сообщений именно в этот канал и переходимой ссылкой на канал, если она определима

#### Scenario: Канал без переходимой ссылки

- **WHEN** канал — «базовая» (не апгрейженная) группа Telegram без публичного username и без числового id супергруппы
- **THEN** строка канала в разбивке всё равно присутствует, ячейка ссылки — пустая

#### Scenario: Канал без отправок в отчётный день

- **WHEN** канал был просмотрен монитором, но сообщений в него в отчётный день не отправлялось
- **THEN** канал не появляется строкой в разбивке
