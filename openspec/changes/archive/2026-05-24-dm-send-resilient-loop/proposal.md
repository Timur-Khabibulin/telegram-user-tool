## Why

Текущий алгоритм dm-send выбирает фиксированный пул из 10–15 кандидатов через LLM перед отправкой. Если у нескольких кандидатов устаревший `accessHash` (ошибка `peer_id_invalid`), весь пул исчерпывается без единой успешной отправки — при том, что в очереди ещё сотни валидных кандидатов.

## What Changes

- **Убрать** LLM-шаг выбора топ 10–15 кандидатов
- **Заменить** его простой сортировкой всей очереди по `score DESC`
- **Добавить** лимит за один прогон: не более 2 успешных отправок (`sentThisRun`)
- **Изменить** поведение при `peer_id_invalid`: помечать кандидата `skipped` и продолжать цикл (не останавливаться)
- **Условия остановки цикла**: `sentThisRun >= 2`, `sentToday >= 15`, `peer_flood`, `floodErrors >= 5`, кандидаты закончились
