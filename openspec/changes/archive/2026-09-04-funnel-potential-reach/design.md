## Context

Воронка собирается в `funnel-collect.ts` (один проход по агентам, без MTProto-сессии)
и рендерится в `funnel-report.ts` (текстовое сообщение + CSV). Данные агента хранятся
в двух раздельных БД: `tg-replies.db` (ответы) и `tg-channels.db` (каналы с кэшированным
`avg_views`). `avg_views` заполняется скриптом channel-coverage-update (раз в месяц).

## Goals / Non-Goals

**Goals:**
- Добавить метрику `potentialReach` в `AgentFunnelRow` без нарушения существующего паттерна сбора
- Вывести метрику как столбец в text-таблице и в CSV
- Корректно обработать отсутствие БД и NULL-значения avg_views

**Non-Goals:**
- Разбивка потенциального охвата по каналам внутри агента
- Дельта потенциального охвата к предыдущему дню
- Дозапрос avg_views через MTProto (если avg_views = NULL — игнорируем)

## Decisions

**Два отдельных запроса вместо ATTACH.**
`funnel-collect.ts` уже работает с двумя БД агента раздельно — не вводим ATTACH,
чтобы не нарушать установленный паттерн. Запрос 1: DISTINCT chatId из replies.db за
окно. Запрос 2: SUM(avg_views) из channels.db по этим chatId.

**Расположение столбца «Охват» — шестым после «Отпр».**
Естественное продолжение: логически охват связан с этапом отправки (Отпр).

**COALESCE(SUM(...), 0) + игнорирование NULL.**
Если avg_views = NULL (канал ещё не пересчитан), строка не включается в сумму —
метрика занижена, но не ломается. Возвращаем 0, а не null, чтобы `AgentFunnelRow`
оставался простым числовым полем без nullable-обработки на уровне рендера.

**readonly-открытие БД.**
Обе функции открывают БД только для чтения — сбор метрик не должен вносить побочных
эффектов в данные агента.

## Risks / Trade-offs

**[Занижение метрики]** → Если у части каналов avg_views = NULL (не пересчитан), охват
будет занижен без явного предупреждения. Митигация: в будущем — предупреждение о доле
NULL в легенде отчёта (future work в design doc).

**[Ширина text-таблицы]** → Добавление столбца «Охват» увеличивает ширину строки.
Значения охвата могут быть большими (5–6 цифр), таблица выйдет за ~40 символов на
мобильном Telegram. Принято осознанно: оператор работает преимущественно с десктопа.
