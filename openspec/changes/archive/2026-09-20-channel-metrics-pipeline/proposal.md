## Why

Подготовка списка каналов к распределению сегодня — ручная цепочка из 3–4 шагов
(ниша → метрики → выгрузка в Google-таблицу → ручная фильтрация → CSV в бот).
Каждый шаг оператор запускает отдельным ops-скриптом по SSH и вручную склеивает
результаты. Это долго, требует разработчика в цикле и не масштабируется на
регулярные прогоны по тысячам каналов. Нужен один вход: оператор присылает боту
CSV со ссылками и параметрами — и получает готовый отфильтрованный CSV, а полный
результат сам ложится в общую Google-таблицу.

## What Changes

- Новая команда в существующем боте распределения (`distribution-listener`):
  принимает **одним сообщением** CSV со ссылками (колонка `link`) + параметры в
  подписи — список агентов (из отдельного пула, выделенного под расчёт метрик),
  имя колонки-фильтра и порог.
- Новый **объединённый скрипт метрик**: за один резолв канала считает всё, что
  сейчас дают три отдельных скрипта — нишу (LLM), `subs_count`, `avg_views`,
  `comments_open`, `is_broadcast`, `posts_30d`, `total_comments`,
  `comments_per_day`. Волнами по заданным агентам, с session-lock, обработкой
  `FLOOD_WAIT` и резюмируемостью по output-CSV (переиспользует машинерию
  `channel-niche.ts`). Несчитаемые/ошибочные поля остаются пустыми.
- **Дедуп входа** против Google-листа `all-processed-channels` по `link` до
  расчёта: уже посчитанные каналы в прогон не берутся.
- **Фильтр**: числовая колонка `>` порог; каналы с непосчитанной метрикой
  (ошибка/не найден) не проходят.
- **Синхронизация с Google Sheets**: по завершении прогона все посчитанные каналы
  дописываются в лист `all-processed-channels` одним пакетом — метрики +
  `источник_ниши`/`источник_метрик` = дата прогона + новая колонка
  `прошёл_фильтр` (TRUE/FALSE для всех). Колонка `assigned_agent` не трогается.
- **Выход в чат**: CSV только прошедших фильтр каналов (`link` + метрики) — его
  оператор дальше сам скармливает распределению.
- **Асинхронное исполнение**: расчёт (часы) идёт в отдельном процессе-воркере,
  бот остаётся отзывчивым; команда `/status` показывает прогресс (посчитано N из
  M); одновременно допускается один прогон.
- Распределение в пайплайн **не входит** — остаётся отдельным ручным шагом
  (существующий `/distribute`), поведение `channel-distribution` не меняется.

## Capabilities

### New Capabilities
- `channel-metrics-pipeline`: сквозной конвейер «CSV ссылок → расчёт всех метрик
  волнами по пулу агентов → дедуп и запись в Google-лист → фильтр → CSV
  прошедших», запускаемый командой бота, исполняемый асинхронным воркером с
  трекингом прогресса через `/status`.

## Impact

- **Код**: новый ops-скрипт объединённого расчёта метрик; новая команда и
  состояние диалога в `src/scripts/periodic/distribution-listener.ts`; запуск
  detached-воркера; новый модуль интеграции Google Sheets; расширение
  `distribution-bot-api` отправкой документа (`sendDocument`).
- **Данные**: новая таблица задач пайплайна в SQLite (id, статус, агенты, фильтр,
  total/processed, пути файлов) для `/status` и guard «один прогон за раз».
- **Зависимости**: новый npm-пакет для Google API (`googleapis` или
  `google-auth-library` + REST); сервис-аккаунт Google с Editor-доступом к
  таблице, scope `spreadsheets`.
- **Конфигурация/секреты**: ID таблицы, имя листа, путь к JSON-ключу
  сервис-аккаунта — в конфиг/секреты (`docs/configuration.md`).
- **Инфраструктура**: возможен отдельный systemd-юнит для воркера; деплой
  JSON-ключа на VPS. Пул агентов под расчёт метрик — операторская настройка входа.
- **Не затрагивается**: существующие `channel-metrics.ts`,
  `channel-activity-update.ts`, `channel-niche.ts` и поток `/distribute`.
