## Why

Платформа мониторит десятки каналов на агента, но нигде не хранит смысл того, о чём
эти каналы и для кого они пишут — только служебное состояние обхода (`channels`).
Оператор не может понять «что это за канал» без ручного захода в Telegram, а система
не может использовать это понимание при принятии решений (например, в monitor-v4 при
оценке, стоит ли комментировать пост). Нужен фоновый механизм, который регулярно
разбирает содержание каждого канала и сохраняет краткое описание рядом с ним.

## What Changes

- Новая фоновая способность `channel-context`: по каждому резолвленному каналу агента
  собираются название, описание (`about`), текст закреплённого поста, посты за
  последние 90 дней (не более 100 штук) и комментарии к ним; один LLM-вызов на канал
  формирует свободный текст-описание канала (10-50 строк, без фиксированной структуры).
- Результат сохраняется в `channels` (`channel_context`, `channel_context_updated_at`) —
  персистентно, для последующего потребления кодом (не разовый отчёт оператору).
- Тем же прогоном пересчитываются и перезаписываются `avg_views`/`subs_count` в
  `channels` (общий кэш с существующей `channel-coverage-report` — те же колонки, тот же
  смысл значений). Колонка `coverage_updated_at` этой способностью не используется и не
  изменяется — остаётся в исключительном ведении отдельного скрипта
  `channel-coverage-update.ts`.
- Новый тип периодической задачи диспетчера (по образцу `monitor-v4`/`account-warmup`):
  раз в 8 часов обрабатывает батч из 20 каналов агента, у которых `channel_context`
  никогда не строился или устарел (TTL 90 дней). `banned`/`suspend`-статус канала не
  является причиной пропуска.
- Новый интерактивный OpenClaw-тул для ручного запуска той же логики оператором:
  параметры — список агентов и число каналов на агента; тот же отбор по TTL 90 дней,
  просто с другим лимитом батча.
- Расширение `TelegramService`: получение текста закреплённого поста канала (сейчас
  никто не тянет текст сообщения по id, только дату) и выборка постов канала с
  одновременным ограничением по дате (90 дней) и по количеству (≤100).
- Новый промпт в `src/llm/prompts.ts` для генерации описания канала по about + закрепу +
  постам + комментариям.

## Capabilities

### New Capabilities

- `channel-context`: регулярный фоновый анализ содержания каждого отслеживаемого канала
  агента (описание, закреп, посты, комментарии) с сохранением текстового описания
  канала и пересчитанных подписчиков/охвата в БД; два способа запуска — периодическая
  задача диспетчера и ручной OpenClaw-тул с теми же правилами отбора каналов.

## Impact

- **Код:**
  - `src/core/telegram/service.ts` — новый метод получения текста закреплённого поста
    канала; новая/расширенная выборка постов с ограничением по дате и количеству.
  - `src/core/db/channels.ts` — новые колонки `channel_context`, `channel_context_updated_at`
    (аддитивная миграция, по образцу `migrateStatusColumns`/`migratePostWatchColumns`);
    функции отбора каналов по TTL и записи результата.
  - `src/core/channel-context/run.ts` — новый core-модуль оркестрации (общая логика для
    обоих входов): отбор каналов, сбор данных, LLM-вызов, запись результата, изоляция
    сбоев по каналу и по агенту.
  - `src/skills/channel-context.ts` — новый скилл диспетчера (периодическая задача,
    батч 20, период 8ч), по образцу `monitor-v4.ts` (обработка FLOOD_WAIT через
    `withFloodRetry`/`FloodAbortError`).
  - `src/core/db/tasks.ts`, `src/scripts/dispatcher.ts` — регистрация нового типа задачи
    и его дефолтного расписания.
  - `src/index.ts` — регистрация нового OpenClaw-тула для ручного запуска.
  - `src/llm/prompts.ts` — новый промпт генерации описания канала.
- **Данные:** новые колонки в `channels` (per-agent `tg-channels.db`); `avg_views`/
  `subs_count` получают второго писателя (общий кэш с `channel-coverage-report`).
- **Документация:** `docs/task-scheduling.md` — новая строка в таблице периодических
  задач; `docs/db-schema.puml` — новые колонки `channels`.
- **Явно вне скоупа:** использование `channel_context` внутри monitor-v4 (передача его
  в промпт `generatePostCommentV4` или иной способ) — будущая работа, отдельный change.
  Скрипт `channel-coverage-update.ts` и его расписание не изменяются.
