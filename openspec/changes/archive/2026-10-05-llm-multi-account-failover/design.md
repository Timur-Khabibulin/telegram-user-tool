## Context

Полный технический дизайн — `docs/design/llm-multi-account-failover/architecture.md`
(диаграммы, модель данных, разрешение развилок §9, трассировка R1–R19). Здесь — выжимка
решений, не дублирующая его.

Текущий LLM-слой (`src/llm/client.ts`): один codex-аккаунт + DeepSeek через `ai-fallback`
с `shouldRetryThisError: () => true` — каскад на любую ошибку, без классификации и без
состояния между прогонами. `completeObject` деградирует схему слоями (нативный structured
→ текст → coerce) со слепым `catch {}`, который глотает любую ошибку слоя 1.

## Goals / Non-Goals

**Goals:**
- Пул codex-слотов с failover по строгому приоритету, DeepSeek последним.
- Классификация ошибок по 7 классам и поведение по классу (повтор только при `usage_limit`
  и `auth_401`).
- cooldown слота до `reset_at` из `/wham/usage`, проверка доступности по дате, host-level
  стор.
- Изоляция ошибки по рабочему элементу (`LlmCallError`) — один сбойный элемент не роняет
  прогон.

**Non-Goals:**
- Починка `.optional()`/`.nullish()` в других схемах (кроме уже исправленного monitor-v5).
- Баланс/пополнение DeepSeek и деградация при полном исчерпании codex.
- Проактивный дашборд расхода квот; релогин/провижининг OAuth-токенов; перевод
  gateway-агента с sol.

## Decisions

- **Убрать `ai-fallback`, ввести явный цикл `withFailover`** — булев `shouldRetryThisError`
  не выражает поклассовое поведение + пропуск по cooldown до вызова.
- **Классификатор** — чистая функция `classifyLlmError` в `src/llm/error-class.ts` по
  `APICallError` (`statusCode`/`responseBody`/`responseHeaders`) и типу JS-исключения.
- **Источник reset** — эндпоинт `/wham/usage` реактивно при `usage_limit` (заголовки
  `x-codex-*` ненадёжны); фолбэк-окно 5 ч при его недоступности (§9-D).
- **cooldown-стор** — host-level `~/.openclaw/codex-cooldown.db` (WAL), ключ = имя слота,
  `cooldown_until` сам себе TTL (§9-A).
- **Пул** — `~/.openclaw/codex-auth/<slot>/auth.json`, приоритет через `CODEX_ACCOUNTS` +
  автодискавери, легаси `auth.json` = слот `default` (§9-B).
- **401** — библиотека сама рефрешит токен; 401 долетает лишь при мёртвом refresh-token →
  один форс-рефреш + повтор на том же слоте, иначе лог без каскада (§5 спайк 4).
- **Изоляция** — `LlmCallError` наружу; ловится per-item `catch` скилла как `ChannelSkipError`.
- Модель `gpt-6-luna` фиксирована; `DEEPSEEK_API_KEY` остаётся обязательным (§9-C, §9-E).

## Risks / Trade-offs

- **Риск скоррелированной блокировки пула** (совместная эксплуатация нескольких подписок
  нарушает ToS) — принят владельцем, вне scope.
- **Квота аккаунта делится с gateway-агентом** (`openclaw.json`, модель sol, профиль
  `openai:chatgpt-default`) — он в пул не входит, расход на аккаунт #1 асимметричен;
  зафиксировано как зависимость, механизму failover прозрачно (считает суммарный остаток).
- **Полное исчерпание codex + мёртвый DeepSeek** → вызовы падают, элементы пропускаются
  (деградация принята как Non-Goal).
- **Правка слепого `catch` в `completeObject`** — тонкое место: ошибка в условии «класс ≠
  schema_error» может либо маскировать провайдерную ошибку (как сейчас), либо зациклить
  текстовый путь; требует аккуратности при реализации.
- **Допущения API библиотеки** (`loadAuthTokens`/рефреш, поля `APICallError`) — часть
  подтверждена сигнатурами, часть требует проверки по факту при реализации.
