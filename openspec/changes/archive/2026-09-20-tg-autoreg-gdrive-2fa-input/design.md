# Design — tg-autoreg-gdrive-2fa-input

## D1 — Источник-агностичный вход, детект в download-слое

Скилл принимает единый список `links`; оператор не различает Mega/GDrive. Вид
источника определяется в download-слое по URL:

- `mega.nz/folder/...` → существующий путь `megajs` (дерево → папка `tdata`).
- `drive.google.com/file/d/<FILE_ID>/...` → GDrive-загрузчик (ниже).

Один диспетчер `downloadTdata(link, destTdataDir)` выбирает реализацию. Нераспознанный
вид ссылки → ошибка аккаунта (`setup_failed` с понятным текстом), прогон продолжается.

## D2 — GDrive-загрузчик

- Извлечь `FILE_ID` из `/file/d/<FILE_ID>/`.
- Скачать прямым запросом. Для больших файлов Google отдаёт HTML-интерстишл
  «не удалось проверить на вирусы» с confirm-token — обработать: распознать HTML,
  вытащить токен, повторить запрос с ним. Для мелких файлов интерстишла нет.
- Если пришёл HTML вместо бинарного ZIP (например, доступ не «всем по ссылке») —
  не пытаться распаковать, а завершить аккаунт понятной ошибкой.

## D3 — Распаковка ZIP: pure-JS, без нативных модулей

Формат архива — ZIP (подтверждено оператором). Деплой проекта — копирование
исходников + `tsx`, без `npm run build` и без нативных аддонов (кроме
better-sqlite3). Значит распаковщик — **pure-JS** (кандидаты: `fflate`,
`adm-zip`, `unzipper`), не нативный и не зависящий от системного `unzip`.
Выбор конкретного пакета — на этапе реализации; критерий: pure-JS, поддержка
распаковки в директорию, живой мейнтенанс. Внутри распакованного дерева папка
`tdata` ищется рекурсивно (переиспользовать существующий `findTdataFolder`).

## D4 — 2FA-пароль из входа, один на пачку

Новый обязательный параметр `twoFaPassword`. Он передаётся как «текущий пароль»
в `change2FA(currentPassword → template.defaultAgentData["2fa"])`. Один на весь
прогон (все аккаунты в поставке имеют один и тот же текущий 2FA). `tdata/Password2FA.txt`
не читается. Смена 2FA на общий пароль из шаблона персоны — без изменений.

## D5 — Телефон из getMe(), сайдкары не читаются

`phoneNumber` берётся из `client.getMe().phone` на bootstrap-сессии (источник
истины — сам аккаунт), затем используется при sign-in второй (агентской) сессии.
`tdata/Accounts.txt` не читается. Итого функция `readTdataAccountInfo` (читала
оба txt) упраздняется: телефон — из `getMe()`, 2FA — из параметра. Папка `tdata`
используется только как источник сессии для `connectBootstrap`.

## D6 — Переименование megaLinks → links (ломающее)

`megaLinks` → `links`. Совместимость со старым именем не держим: интерфейс
операторский, вызывается через скилл вручную, риск скрытого использования нулевой.
Чистое имя точнее отражает источник-агностичность.

## D7 — twoFaPassword как чувствительный ввод (принятый риск)

2FA-пароль идёт аргументом тула и через диалог скилла → попадает в
логи/транскрипт. Прогон — ручной операторский, пароль у пачки общий и после
регистрации всё равно меняется на пароль из шаблона. Риск принимается, спец-маскировку
не вводим.

## Открытые вопросы реализации (не блокеры дизайна)

- Ретрай-путь `tg_agent_autoregistration_retry_code`: убедиться, что он не читает
  упразднённые сайдкары и не пере-качивает архив (сейчас берёт только телефон).
- Точный пакет для ZIP (D3).
