## MODIFIED Requirements

### Requirement: Выбор локации прокси — два режима

Система SHALL запросить у юзера только код страны (`countryCode`) для подбора прокси — либо
текстом напрямую, либо выбором из списка `/dir/countries`. Пошаговый подбор региона/города SHALL
NOT предлагаться — источник кандидатов (`/proxy/search`) не поддерживает фильтрацию по региону
или городу.

#### Scenario: Юзер вводит код страны

- **WHEN** юзер вводит `countryCode` текстом
- **THEN** система принимает его напрямую, без дополнительных обращений к провайдеру прокси на
  этом шаге

#### Scenario: Юзер выбирает страну из списка

- **WHEN** юзер запрашивает список доступных стран
- **THEN** система показывает список из `/dir/countries`, юзер выбирает одну страну

### Requirement: Автоматический подбор прокси до авторизации сессии

Система SHALL подобрать рабочий мобильный прокси до входа в Telegram-аккаунт (до вызова отправки
кода авторизации): взять следующего ещё не использованного (ни одним другим агентом, см.
`mobile-proxy-provisioning`) кандидата из инвентаря asocks для выбранной страны, проверить его
MTProto-подключением без отправки кода авторизации, при неудаче перейти к следующему кандидату —
до `maxAttempts`. Кандидаты SHALL NOT создаваться или удаляться на стороне asocks. Отправка кода
авторизации SHALL использовать только подтверждённый рабочий прокси.

#### Scenario: Рабочий прокси найден

- **WHEN** один из кандидатов проходит проверку подключения
- **THEN** дальнейшие кандидаты не берутся, найденный прокси используется для входа в аккаунт и
  сохраняется в `tg-account.json` вместе со страной (`countryCode`)

#### Scenario: Кандидат не проходит проверку

- **WHEN** кандидат не проходит проверку подключения
- **THEN** система берёт следующего ещё не использованного кандидата из того же списка, ничего не
  удаляя на стороне asocks, попытки продолжаются до успеха или до исчерпания `maxAttempts`

#### Scenario: Все попытки исчерпаны

- **WHEN** ни один из `maxAttempts` кандидатов не прошёл проверку
- **THEN** юзеру явно сообщается, что рабочий прокси не найден за N попыток, вход в аккаунт не
  выполняется

#### Scenario: Проверка кандидата не отправляет код авторизации

- **WHEN** система проверяет кандидата прокси
- **THEN** проверка выполняется только установлением и разрывом MTProto-соединения, без вызова
  отправки кода авторизации Telegram — реальный код запрашивается только один раз, после того как
  рабочий прокси уже подтверждён
