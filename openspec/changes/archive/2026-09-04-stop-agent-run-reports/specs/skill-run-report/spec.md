## REMOVED Requirements

### Requirement: Отчёт прогона — человекочитаемый текст

**Reason**: Диспетчер больше не отправляет отчёт о прогоне в Saved Messages ни для одного рабочего агента (см. `task-scheduler`) — вся диагностика прогонов ведётся через `runs`/`dispatcher_runs`/`error_log` (см. `run-log`). Человекочитаемый рендер отчёта отправлять некуда, требование неприменимо.

**Migration**: Для просмотра исхода прогона — запрос к `runs` (per-agent `tasks.db`), не Saved Messages. `SkillStatus.details` по-прежнему вычисляется скиллами, но нигде не сохраняется и не рендерится.

### Requirement: Длительность прогона в отчёте

**Reason**: Отчёт в Saved Messages больше не отправляется — показывать длительность в его шапке негде. Сама длительность продолжает записываться в `runs.durationMs` (см. `run-log`).

**Migration**: Длительность прогона — колонка `durationMs` в `runs`.

### Requirement: Количество LLM-запросов в отчёте

**Reason**: Отчёт в Saved Messages больше не отправляется. Счётчик запросов к LLM продолжает записываться в `runs.llmCalls` (см. `run-log`).

**Migration**: Число LLM-запросов прогона — колонка `llmCalls` в `runs`.

### Requirement: Состав отчёта monitor

**Reason**: Разбивка ответов `monitor` («каналов обработано», «ответов отправлено» по типам, «dm-кандидатов добавлено») формировалась исключительно для текста отчёта в Saved Messages. Отчёт удалён — требование к его составу неприменимо. Скилл `monitor` продолжает вычислять и возвращать этот `details`-объект в `SkillStatus` (код скилла не меняется), но диспетчер его больше никуда не рендерит и не сохраняет целиком.

**Migration**: Нет замены — при необходимости эта разбивка используется только внутри процесса (например, для логики самого скилла), персистентность вне скоупа этого change.

### Requirement: Состав отчёта account-warmup

**Reason**: Поле «ответ» формировалось для текста отчёта в Saved Messages. Отчёт удалён — требование к его составу неприменимо. Скилл `account-warmup` продолжает вычислять и возвращать `details` как прежде.

**Migration**: Нет замены — вне скоупа этого change.

## ADDED Requirements

### Requirement: Капабилити неактивна

Диспетчер SHALL NOT формировать и отправлять человекочитаемый отчёт прогона
в Saved Messages ни для одного рабочего агента — вся диагностика прогонов
ведётся через `runs`/`dispatcher_runs`/`error_log` (см. `run-log`). Все
предыдущие требования этой капабилити (рендер, длительность, счётчик
LLM-запросов, состав по типам скиллов) удалены как неприменимые; `details`
скиллов по-прежнему вычисляется кодом скиллов, но нигде не рендерится и не
сохраняется целиком.

#### Scenario: Отчёт в Saved Messages не формируется
- **WHEN** диспетчер завершает прогон любого скилла
- **THEN** в Saved Messages агента отчёт о прогоне не отправляется; исход прогона доступен через `runs` (per-agent `tasks.db`)
