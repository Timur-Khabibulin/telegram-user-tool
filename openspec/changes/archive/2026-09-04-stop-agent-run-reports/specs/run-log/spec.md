## MODIFIED Requirements

### Requirement: Запись прогона в таблицу runs

Диспетчер SHALL после каждого выполнения скилла записывать в таблицу `runs` (в per-agent `tasks.db`) строку со всеми полями прогона: `agentId`, `type` (тип скилла), `startedAt` (Unix-секунды начала прогона), `durationMs` (длительность), `status` (`success`|`error`), `error` (текст ошибки при `status = error`, иначе пусто), `llmCalls` (число фактических запросов к LLM за прогон), потребление CPU скиллом (пользовательское и системное время, в миллисекундах). Запись SHALL выполняться для каждого прогона независимо от исхода (и `success`, и `error`). Сбой записи в `runs` SHALL НЕ прерывать прогон диспетчера.

#### Scenario: Успешный прогон записан
- **WHEN** скилл завершился со статусом `success`
- **THEN** в `runs` появляется строка с `status = success`, заполненными `agentId`, `type`, `startedAt`, `durationMs`, `llmCalls`, CPU-потреблением и пустым `error`

#### Scenario: Ошибочный прогон записан с текстом ошибки
- **WHEN** скилл завершился со статусом `error`
- **THEN** в `runs` появляется строка с `status = error` и непустым `error`, извлечённым из `details` прогона

#### Scenario: CPU измеряется вокруг вызова скилла
- **WHEN** диспетчер вызывает скилл
- **THEN** снимок потребления CPU процесса снимается непосредственно до и сразу после вызова; разница между снимками записывается в `runs` как CPU-потребление этого прогона

#### Scenario: Сбой записи не валит прогон
- **WHEN** запись в `runs` бросила исключение
- **THEN** диспетчер логирует ошибку и продолжает работу (сдвиг `nextRun` не отменяется)
