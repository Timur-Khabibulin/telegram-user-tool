## ADDED Requirements

### Requirement: Пропуск агентов с несовместимым ограничением на этапах охвата

Перед снятием снапшота охвата публичного канала (просмотры поста, число подписчиков) и заявок в приватный канал по конкретному агенту система SHALL проверять активное ограничение агента (`agent_restrictions`, `getActiveRestriction`). Если `restriction_type` агента — `need_update_session` или `banned`, MTProto-подключение SHALL не выполняться для этого агента на этих метриках, попытка пропускается без установки пометки о сбое сбора (см. `funnel-report`, «Пометки о пропущенных данных»). Ограничение `suspend` SHALL не приводить к пропуску — сессия остаётся рабочей, ограничена только отправка.

#### Scenario: Агент с need_update_session пропущен без попытки подключения
- **WHEN** у агента активна запись `agent_restrictions` с `restriction_type = need_update_session`
- **THEN** система не вызывает `tg.loadAccount`/MTProto для этого агента на этапах охвата, снапшот не снимается, `note5to7` не устанавливается

#### Scenario: Агент с banned пропущен без попытки подключения
- **WHEN** у агента активна запись `agent_restrictions` с `restriction_type = banned`
- **THEN** система не вызывает `tg.loadAccount`/MTProto для этого агента на этапах охвата, снапшот не снимается, `note5to7` не устанавливается

#### Scenario: Агент с suspend не пропускается
- **WHEN** у агента активна запись `agent_restrictions` с `restriction_type = suspend`
- **THEN** система выполняет попытку снятия снапшота как обычно, ограничение не влияет на этот шаг

#### Scenario: Локальные метрики (этапы 1-4) не зависят от ограничения
- **WHEN** у агента активное ограничение любого типа (`need_update_session`, `banned` или `suspend`)
- **THEN** метрики из локальных БД агента (число каналов, ответы в группах, ошибки отправки) собираются как обычно — эти метрики не требуют MTProto-подключения
