## Why

Тематический LLM-гейт `discovery-similar` дорог (вызов модели на каждого кандидата) и не
отсекает каналы, которые тематически подходят, но фактически «мёртвые» или мелкие по
вовлечённости. Нужен дешёвый гейт по вовлечённости (ER и средние просмотры на пост) перед
LLM-вызовом, чтобы не тратить его на заведомо неинтересные находки. ТЗ зафиксировано
оператором — см. `docs/design/channel-discovery-similar/er-views-gate-v1.md`.

## What Changes

- Новый гейт кандидата «ER/avg views» — встаёт между гейтом группы обсуждения и
  тематическим LLM-гейтом: `подписчики → группа обсуждения → ER/avg views → тема (LLM)`.
- Метрики считаются по последним 20 постам канала минус 2 самых свежих (просмотры «не
  дозрели»): `avgViews` — среднее просмотров по выборке, `ER = avgViews / подписчики`.
  Закреплённые посты не фильтруются. Пустая выборка (≤2 постов у канала) — fail-closed.
- Новые параметры прогона: `minAvgViews` (обязательный, без дефолта) и
  `minEngagementRate` (опциональный, дефолт `0.1`). Кандидат отсеивается, если хотя бы одно
  значение не строго больше своего порога.
- Один агрегированный счётчик отсева `lowEngagement` (без разбивки на под-причины),
  отображается в отчёте оператору рядом с существующими причинами отсева.
- Принятые кандидаты — ER и avg views добавляются в существующую строку лога. Отклонённые
  по этому гейту построчно не логируются.
- **Изменение существующего поведения:** окно оценки вовлечённости отправных точек
  (seed-приоритизация) переходит с дневного (`engagementWindowDays`) на оконное правило по
  числу постов — то же самое, что у нового гейта (последние посты минус 2 свежих). Агрегация
  для отправных точек остаётся медианой (не average) — устойчивость к выбросам для seeds не
  меняется.

## Capabilities

### New Capabilities

(нет — это уточнение существующей способности)

### Modified Capabilities

- `similar-channel-discovery`: добавляется требование «Гейт вовлечённости кандидата»; меняются
  требования «Запуск обхода оператором» (новые параметры), «Отчёт оператору» (новая причина
  отсева), «Лог принятых кандидатов» (новые поля ER/avg views) и «Приоритизация отправных
  точек по вовлечённости» (окно по числу постов вместо дней).
