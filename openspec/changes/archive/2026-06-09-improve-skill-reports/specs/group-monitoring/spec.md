## MODIFIED Requirements

### Requirement: Agent uses tg_classify_messages to split messages into categories

После вызова `telegram_mark_as_read` агент SHALL вызывать `tg_classify_messages` для разбивки входящих сообщений на категории. Агент SHALL НЕ вызывать `tg_group_thread_find` или `tg_replies_find_by_reply_msg_id` напрямую — эти инструменты больше не доступны.

Порядок обработки для каждого канала:
1. `telegram_get_messages` → сырые сообщения
2. `telegram_mark_as_read`
3. `tg_classify_messages` → `{ generalMessages, newThreadMessages, threadReplies }`
4. Обработать `newThreadMessages` (создать треды, ответить)
5. Обработать `threadReplies` (ответить, включая expired)
6. Обработать `generalMessages` — **одним структурированным LLM-вызовом** на канал, который одновременно: (а) выбирает не более одного сообщения для ответа и (б) скорит сообщения как DM-кандидатов. Отдельного шага извлечения тем (`extractTopics`) больше нет.

Обработка `generalMessages` SHALL:
- сначала отбрасывать дешёвой эвристикой (без LLM) заведомо непроходные сообщения (слишком короткие, только эмодзи/пунктуация, без буквенных символов);
- выполнять **один** структурированный LLM-вызов на канал, возвращающий выбор сообщения для ответа (или его отсутствие) и список оценок DM-кандидатов;
- отправлять **не более одного ответа** на канал за прогон;
- записывать DM-кандидатов по прежнему критерию (`score >= 0.6`) и с прежним набором полей.

#### Scenario: tg_classify_messages called after mark_as_read
- **WHEN** агент получил непустой список сообщений из `telegram_get_messages`
- **THEN** агент вызывает `telegram_mark_as_read`, затем вызывает `tg_classify_messages` с теми же сообщениями; результат классификации используется для дальнейшей обработки

#### Scenario: expired thread reply is handled by skill
- **WHEN** `tg_classify_messages` возвращает `ThreadReplyEntry` с `threadStatus = 'expired'`
- **THEN** агент отвечает на сообщения в этом записанном треде (обрабатывает как продолжение диалога), не перекладывает их в `generalMessages`

#### Scenario: Empty category is skipped
- **WHEN** одна из категорий (`generalMessages`, `newThreadMessages`, или `threadReplies`) пуста
- **THEN** агент пропускает шаг обработки этой категории без ошибок

#### Scenario: generalMessages обрабатываются одним LLM-вызовом
- **WHEN** после классификации `generalMessages` непуст
- **THEN** выполняется один структурированный LLM-вызов на канал, возвращающий выбор сообщения для ответа и оценки DM-кандидатов; отдельные вызовы извлечения тем не выполняются

#### Scenario: Не более одного ответа на канал
- **WHEN** структурированный вызов выбрал сообщение для ответа
- **THEN** агент отправляет ровно один ответ в этот канал за прогон

#### Scenario: Нечего отвечать
- **WHEN** структурированный вызов вернул отсутствие подходящего сообщения для ответа
- **THEN** агент не отправляет ответ в общий поток канала, но всё равно может записать DM-кандидатов из оценок

#### Scenario: Префильтр отбрасывает реакции до LLM
- **WHEN** среди `generalMessages` есть слишком короткие сообщения / только эмодзи / без буквенных символов
- **THEN** они отбрасываются эвристикой и не попадают в структурированный LLM-вызов
