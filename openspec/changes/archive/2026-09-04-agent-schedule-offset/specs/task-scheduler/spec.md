## MODIFIED Requirements

### Requirement: Управление расписанием из Telegram
Расписанием SHALL можно управлять из Telegram: создать / остановить / запустить внепланово. OpenClaw-скилл не запускает задачу напрямую — он управляет строками в таблице `tasks` и включает/выключает heartbeat-таймер агента. Если при создании/изменении задачи `schedule` не передан явно, он SHALL вычисляться автоматически так, чтобы дефолтная фаза старта была гарантированно равномерно распределена между агентами, имеющими задачу этого же `type` (round-robin по числу уже существующих агентов с включённой задачей данного типа, а не статический дефолт, одинаковый для всех агентов). Период задачи (интервал между запусками) SHALL сохраняться неизменным — распределяется только фаза старта внутри периода. Явно переданный пользователем `schedule` SHALL использоваться как есть, без пересчёта.

#### Scenario: Первая задача агента включает таймер
- **WHEN** скилл создаёт первую задачу агента (`INSERT ... ON CONFLICT(agentId, type) DO UPDATE`)
- **THEN** дополнительно выполняется `systemctl enable --now tg-agent@<agentId>.timer`

#### Scenario: Вторая задача того же агента
- **WHEN** скилл добавляет вторую задачу агенту, у которого таймер уже крутится
- **THEN** выполняется только INSERT, таймер не трогается

#### Scenario: Внеплановый запуск
- **WHEN** скилл выставляет `UPDATE tasks SET nextRun='now'` и вызывает `systemctl start tg-agent@<agentId>.service`
- **THEN** если сервис свободен — диспетчер стартует сразу и видит `nextRun=now`; если занят — start-job коалесцируется и выполнится после текущего прогона

#### Scenario: Не осталось активных задач
- **WHEN** у агента не осталось активных задач
- **THEN** выполняется `systemctl disable --now ...timer`

#### Scenario: Дефолтная фаза распределяется round-robin
- **WHEN** создаётся задача `type=monitor` без явного `schedule`, и уже существует N других агентов с включённой задачей `monitor`
- **THEN** новой задаче присваивается слот `N % N_SLOTS(monitor)` (где `N_SLOTS = период / тик`), и итоговый `schedule` смещён на `slot * тик` минут относительно базовой фазы (0)

#### Scenario: Явный schedule не пересчитывается
- **WHEN** пользователь явно передал `schedule` при создании/изменении задачи
- **THEN** используется переданное значение как есть, round-robin не применяется

#### Scenario: Период сохраняется, меняется только фаза
- **WHEN** round-robin вычисляет дефолтный `schedule` для задачи с базовым периодом `P`
- **THEN** интервал между последовательными срабатываниями остаётся `P`, отличается только момент первого срабатывания внутри периода
