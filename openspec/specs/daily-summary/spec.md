## Requirements
### Requirement: Агрегированная дневная сводка по всем агентам

Система SHALL формировать дневную сводку прогонов по **всем** агентам за календарный день (граница дня — UTC+5). Сводка SHALL читать таблицы `runs` всех агентов (обход всех `~/.openclaw/workspace-*`). Чистая логика `features/funnel/runs-summary.ts:buildDailySummary(window)` SHALL агрегировать записи и возвращать структуру и человекочитаемый текст. Структурная часть SHALL включать по каждому агенту и типу скилла: число прогонов, успехов, ошибок, суммарное число LLM-запросов, суммарную длительность. Человекочитаемый текст SHALL содержать общий итог по всем агентам (всего прогонов, успехов, ошибок, LLM-запросов, суммарное время) и **список ошибок**, сгруппированных по (агент, тип скилла, текст ошибки) с числом повторов; текст SHALL НЕ перечислять всех агентов по скиллам.

#### Scenario: Текст содержит общий итог
- **WHEN** сводка построена при наличии прогонов
- **THEN** в шапке текста есть общий итог по всем агентам (всего прогонов, успехов, ошибок, LLM-запросов, время)

#### Scenario: Текст содержит список ошибок
- **WHEN** за день были прогоны со статусом `error`
- **THEN** текст содержит секцию ошибок, где для каждой группы (агент, тип скилла, текст ошибки) указано число повторов

#### Scenario: Ошибок не было
- **WHEN** за день были прогоны, но ни одного со статусом `error`
- **THEN** текст сообщает, что ошибок нет, и не содержит секции со списком ошибок

#### Scenario: Структурная разбивка доступна программно
- **WHEN** вызывается `buildDailySummary`
- **THEN** в возвращаемой структуре есть разбивка по каждому агенту и типу скилла (прогоны/успехи/ошибки, LLM-запросы, длительность), даже если текст её не печатает

#### Scenario: Граница дня по UTC+5
- **WHEN** строится сводка за день
- **THEN** в окно попадают прогоны с `startedAt` внутри суток по UTC+5, а не по UTC

#### Scenario: Нет прогонов за день
- **WHEN** ни у одного агента нет записей `runs` в окне
- **THEN** сводка корректно формируется и сообщает об отсутствии прогонов

### Requirement: Перечисление агентов

`core/config.ts` SHALL предоставлять `listAgentIds()`, возвращающий идентификаторы всех
агентов по директориям `~/.openclaw/workspace-<agentId>`, за исключением
`REPORT_AGENT_ID` — он не возвращается, даже если его workspace-каталог существует.

#### Scenario: Перечисление по директориям workspace

- **WHEN** вызывается `listAgentIds()`
- **THEN** возвращаются `agentId` из всех каталогов `workspace-*`, кроме `REPORT_AGENT_ID`

#### Scenario: Зарезервированный агент не входит в сводку

- **WHEN** строится дневная сводка прогонов
- **THEN** `REPORT_AGENT_ID` не обходится и не появляется в структурной разбивке `perAgent`, даже если у него есть workspace-каталог

### Requirement: Сводка по запросу через OpenClaw-пульт

OpenClaw-инструмент `tg_daily_summary` (и скилл `skills/daily-summary/SKILL.md`) SHALL по запросу строить сводку за текущий день UTC+5 (до момента вызова) и возвращать её текст в чат. Доступный для агента inструмент SHALL переиспользовать `features/funnel/runs-summary.ts` без дублирования логики.

#### Scenario: Сводка за сегодня по запросу
- **WHEN** вызывается `tg_daily_summary`
- **THEN** возвращается текст сводки за текущий день UTC+5 от начала суток до момента вызова

#### Scenario: Переиспользование общей логики
- **WHEN** сводка строится и скриптом, и инструментом
- **THEN** оба используют `features/funnel/runs-summary.ts:buildDailySummary`, без второй копии агрегации

### Requirement: Доставка дневной сводки получателю по расписанию

Standalone-скрипт `src/scripts/periodic/daily-summary.ts --send-as <agentId>` SHALL построить
сводку за завершившийся день UTC+5, загрузить указанный аккаунт через
`TelegramService` и отправить текст сводки в его Saved Messages. Значение по
умолчанию — `REPORT_AGENT_ID`; аргумент допускает явное переопределение. systemd-таймер
`tg-daily-summary.timer` SHALL запускать скрипт раз в день на границе дня UTC+5
(19:00 UTC).

#### Scenario: Сводка ушла в Saved Messages получателя

- **WHEN** отработал `daily-summary.ts` (со значением `--send-as` по умолчанию или явно заданным)
- **THEN** в Saved Messages указанного аккаунта появляется текст дневной сводки за завершившийся день

#### Scenario: Запуск без флага использует REPORT_AGENT_ID

- **WHEN** `daily-summary.ts` запущен без `--send-as`
- **THEN** сводка уходит в Saved Messages `REPORT_AGENT_ID`

#### Scenario: Запуск по таймеру раз в день

- **WHEN** наступает граница дня UTC+5 (19:00 UTC)
- **THEN** `tg-daily-summary.timer` запускает `tg-daily-summary.service`, который формирует и отправляет сводку
