## Requirements

### Requirement: Кандидаты на ротацию

Задача `channel-rotation` SHALL по всем агентам платформы (`listAgentIds()`)
находить каналы в статусе `leaved_from_banned` с заполненным
`channelUsername`, отсортированные по `statusUpdatedAt` по возрастанию
(старые — первыми). Каналы в статусе `leaved_from_banned` без
`channelUsername` SHALL не рассматриваться как кандидаты — передавать их
некому: у платформы нет ссылки для повторного вступления.

#### Scenario: Канал с юзернеймом становится кандидатом

- **WHEN** прогон `channel-rotation` сканирует агентов и находит канал со
  `status='leaved_from_banned'` и непустым `channelUsername`
- **THEN** канал включается в список кандидатов на перенос

#### Scenario: Канал без юзернейма пропускается

- **WHEN** канал имеет `status='leaved_from_banned'`, но `channelUsername`
  пуст (`NULL`)
- **THEN** канал не включается в кандидаты и учитывается отдельным счётчиком
  `skipped_no_username` в итоговой сводке прогона

### Requirement: Активный агент-цель

Агент SHALL считаться доступным для получения ротируемых каналов только если
одновременно выполняются два условия: у него нет активной записи в
`agent_restrictions` (`getActiveRestriction` возвращает `null`), и у него
включена (`enabled=1`) хотя бы одна из задач мониторинга
(`monitor`/`monitor-v2`/`monitor-v3`/`monitor-v4`/`monitor-v5`, то есть
`isAgentActive` возвращает `true`). Агент, у которого канал был забанен, не
исключается из пула целей для ротации ЧУЖИХ каналов — исключение действует
только для его собственного канала (см. «Перенос назначения»).

#### Scenario: Агент с ограничением исключён из целей

- **WHEN** у агента есть активная запись в `agent_restrictions`
- **THEN** этот агент не рассматривается как цель ни для одного кандидата в
  текущем прогоне

#### Scenario: Агент без включённого монитора исключён из целей

- **WHEN** у агента нет ни одной задачи `monitor*` со статусом `enabled=1`
- **THEN** этот агент не рассматривается как цель, даже если у него нет
  ограничений

### Requirement: Распределение по нагрузке (round-robin)

Список активных агентов-целей SHALL быть отсортирован по возрастанию текущей
активной нагрузки (число каналов в статусах, не исключённых фильтром
активности `getChannelsBatch`) один раз в начале прогона; результат
сортировки SHALL зафиксирован на весь прогон и не пересчитывается после
каждого назначения. Кандидаты SHALL распределяться по этому списку
round-robin (по кругу), начиная с наименее загруженного агента. При равенстве
нагрузки порядок между агентами с одинаковым значением SHALL определяться
случайно.

#### Scenario: Единичный кандидат уходит наименее загруженному

- **WHEN** в прогоне ровно один кандидат на ротацию
- **THEN** он назначается агенту с наименьшей активной нагрузкой на момент
  начала прогона

#### Scenario: Пачка кандидатов не оседает на одном агенте

- **WHEN** в прогоне кандидатов больше, чем активных агентов-целей
- **THEN** назначения идут по кругу зафиксированного на старте порядка, и
  после первого полного круга каждый активный агент получил не более чем на
  один канал больше любого другого

### Requirement: Перенос назначения

Для каждого кандидата, которому подобран целевой агент, SHALL выполниться:
регистрация канонической ссылки (`normalizeChannelLink(channelUsername)`) за
новым агентом в реестре `discovered_channels` (переиспользуя существующий
`forceAssignChannel`), постановка этой ссылки в `join_queue` целевого агента
(`addJoinQueue`), и удаление строки канала из таблицы `channels` агента, где
канал был забанен. Целевым агентом для канала SHALL не может быть выбран тот
же агент, у которого этот канал был забанен — при совпадении выбор
round-robin сдвигается на следующего кандидата в списке целей.

#### Scenario: Успешный перенос канала

- **WHEN** кандидат `chatId` у агента A назначен агенту B
- **THEN** `discovered_channels.assigned_agent` для этого канала становится
  B, ссылка канала появляется в `join_queue` агента B, а строка `chatId` в
  `channels` агента A удаляется

#### Scenario: Исходный агент не назначается сам себе

- **WHEN** очередь round-robin по порядку должна выдать канал агенту A, но
  этот канал был забанен именно у агента A
- **THEN** канал получает следующий по порядку доступный агент, а не A

### Requirement: Периодичность запуска

Задача `channel-rotation` SHALL запускаться отдельным систeмным таймером раз
в сутки, кросс-агентно (не через per-agent диспетчер и таблицу `tasks`), по
аналогии с `daily-summary`/`funnel-tracker`. Время запуска SHALL быть выбрано
так, чтобы между прогоном `channel-rotation` и ближайшими прогонами
`leave-banned-channels` проходило не менее 12 часов.

#### Scenario: Отдельный суточный таймер

- **WHEN** наступает время суточного запуска `channel-rotation`
- **THEN** скрипт выполняется один раз, сканирует всех агентов платформы и
  не зависит от расписания `tasks` конкретного агента
