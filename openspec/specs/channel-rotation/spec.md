## Requirements
### Requirement: Кандидаты на ротацию

Задача `channel-rotation` SHALL по всем агентам платформы (`listAgentIds()`)
находить каналы в статусе `leaved_from_banned` с заполненным
`channelUsername`, отсортированные по `statusUpdatedAt` по возрастанию
(старые — первыми). Каналы в статусе `leaved_from_banned` без
`channelUsername` SHALL не рассматриваться как кандидаты — передавать их
некому: у платформы нет ссылки для повторного вступления.

#### Scenario: Канал с юзернеймом становится кандидатом

- **WHEN** прогон `channel-rotation` сканирует агентов и находит канал со
  `status='leaved_from_banned'` и непустым `channelUsername`
- **THEN** канал включается в список кандидатов на перенос

#### Scenario: Канал без юзернейма пропускается

- **WHEN** канал имеет `status='leaved_from_banned'`, но `channelUsername`
  пуст (`NULL`)
- **THEN** канал не включается в кандидаты и учитывается отдельным счётчиком
  `skipped_no_username` в итоговой сводке прогона

### Requirement: Активный агент-цель

Агент SHALL считаться доступным для получения ротируемого канала только если
одновременно: он принадлежит той же персоне, что и агент-источник канала; у него нет
активной записи в `agent_restrictions` (`getActiveRestriction` возвращает `null`); и
у него включена (`enabled=1`) хотя бы одна из задач мониторинга
(`monitor`/`monitor-v2`/`monitor-v3`/`monitor-v4`/`monitor-v5`, то есть
`isAgentActive` возвращает `true`). Агент, у которого канал был забанен, не
исключается из пула целей для ротации ЧУЖИХ каналов своей персоны — исключение
действует только для его собственного канала (см. «Перенос назначения»).

#### Scenario: Агент другой персоны не рассматривается как цель

- **WHEN** канал забанен у агента персоны Б
- **THEN** агенты других персон не рассматриваются как цели для этого канала

#### Scenario: Агент с ограничением исключён из целей

- **WHEN** у агента есть активная запись в `agent_restrictions`
- **THEN** этот агент не рассматривается как цель ни для одного кандидата в текущем
  прогоне

#### Scenario: Агент без включённого монитора исключён из целей

- **WHEN** у агента нет ни одной задачи `monitor*` со статусом `enabled=1`
- **THEN** этот агент не рассматривается как цель, даже если у него нет ограничений

### Requirement: Перенос назначения

Для каждого кандидата, которому подобран целевой агент, SHALL выполниться:
регистрация канонической ссылки (`normalizeChannelLink(channelUsername)`) за
новым агентом в реестре `discovered_channels` (переиспользуя существующий
`forceAssignChannel`), постановка этой ссылки в `join_queue` целевого агента
(`addJoinQueue`), и удаление строки канала из таблицы `channels` агента, где
канал был забанен. Целевым агентом для канала SHALL не может быть выбран тот
же агент, у которого этот канал был забанен — агент-источник исключается из
числа кандидатов на выбор.

#### Scenario: Успешный перенос канала

- **WHEN** кандидат `chatId` у агента A назначен агенту B
- **THEN** `discovered_channels.assigned_agent` для этого канала становится
  B, ссылка канала появляется в `join_queue` агента B, а строка `chatId` в
  `channels` агента A удаляется

#### Scenario: Исходный агент не назначается сам себе

- **WHEN** агент A является источником этого канала (канал был у A забанен)
- **THEN** A исключается из кандидатов, и канал получает другого активного агента
  персоны, а не A

### Requirement: Периодичность запуска

Задача `channel-rotation` SHALL запускаться отдельным систeмным таймером раз
в сутки, кросс-агентно (не через per-agent диспетчер и таблицу `tasks`), по
аналогии с `daily-summary`/`funnel-tracker`. Время запуска SHALL быть выбрано
так, чтобы между прогоном `channel-rotation` и ближайшими прогонами
`leave-banned-channels` проходило не менее 12 часов.

#### Scenario: Отдельный суточный таймер

- **WHEN** наступает время суточного запуска `channel-rotation`
- **THEN** скрипт выполняется один раз, сканирует всех агентов платформы и
  не зависит от расписания `tasks` конкретного агента

### Requirement: Распределение по истории посещений (visit-count)

Система SHALL НЕ учитывать нагрузку агента (число активных каналов) при выборе
целевого агента. Для каждого кандидата система SHALL вычислять `visit-count` каждого
активного агента-цели персоны — число прошлых событий `assigned` по этому каналу для
этого агента-получателя в разрезе персоны (из журнала операций; агент без событий =
visit-count 0). Канал SHALL назначаться активному агенту с минимальным visit-count,
исключая агента-источник; при нескольких агентах с минимальным visit-count выбор
SHALL быть случайным. «Круги» SHALL возникать как следствие правила минимума: пока
есть агенты с visit-count 0 — канал достаётся им; когда у всех подходящих
visit-count ≥ 1, минимум становится 1, и так далее. Выбор для каждого кандидата
независим — общего курсора обхода целей нет.

#### Scenario: Канал уходит агенту, у которого его ещё не было

- **WHEN** в прогоне есть кандидат и среди активных агентов-целей (кроме источника)
  есть агенты с visit-count 0
- **THEN** канал назначается одному из агентов с visit-count 0 (у которого канала ещё
  не было), независимо от их нагрузки

#### Scenario: Случайный выбор среди равных по минимуму

- **WHEN** минимальный visit-count имеют несколько активных агентов-целей
- **THEN** целевым может оказаться любой из них — выбор между ними случайный

#### Scenario: Повтор только после полного круга

- **WHEN** канал уже побывал у всех активных агентов персоны по одному разу
  (у всех visit-count ≥ 1)
- **THEN** канал достаётся агенту с наименьшим visit-count (новый круг), а не
  произвольному ранее пробовавшему

#### Scenario: Нет подходящей цели

- **WHEN** единственный активный агент персоны — источник этого канала
- **THEN** канал остаётся нераспределённым (`unassigned`)

### Requirement: Ротация в рамках персоны источника

Кандидат на ротацию SHALL перераспределяться только на активных агентов той же
персоны, что и агент-источник (персона резолвится из конфига агента). Канал SHALL
NOT переноситься в другую персону. Кандидаты SHALL группироваться по персоне, и
каждая группа распределяется независимо только по активным агентам своей персоны.

#### Scenario: Кандидат уходит агенту своей персоны

- **WHEN** канал забанен у агента персоны Б и есть другой активный агент персоны Б
- **THEN** канал перераспределяется агенту персоны Б, а не агенту другой персоны

### Requirement: Пустой слот при отсутствии активного агента персоны

Если у персоны нет доступного активного агента-цели для кандидата, ротация SHALL
оставить закрепление канала за этой персоной с пустым слотом (`agent_id IS NULL`) и
SHALL NOT переносить канал в другую персону и SHALL NOT удалять закрепление.

#### Scenario: Нет активного агента персоны

- **WHEN** канал забанен у единственного/последнего активного агента персоны Б и
  других доступных активных агентов в персоне Б нет
- **THEN** слот канала в персоне Б становится пустым, принадлежность персоне Б
  сохраняется, канал не уходит в другую персону

### Requirement: Независимая ротация канала в нескольких персонах

Если один и тот же канал забанен сразу в нескольких персонах, ротация SHALL
обрабатывать каждую персону независимо: в персоне с доступным активным агентом слот
заполняется, в персоне без него — остаётся пустым; принадлежность канала каждой из
этих персон сохраняется.

#### Scenario: Бан в двух персонах — разный исход

- **WHEN** канал забанен в персонах А и Б; в А есть активный агент, в Б — нет
- **THEN** слот канала в А заполняется активным агентом А, слот в Б остаётся пустым,
  канал числится за обеими персонами
